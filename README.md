# AgentWorkbench

独立的多运行时 Agent 桌面工作台，以 Claude 工作流和双语阅读为主要设计方向。产品名称为 **AgentWorkbench**，程序及快捷方式没有测试后缀。源码实现、合成测试、真实模型任务及远端部署的完成度分别记录，不互相替代。

## Windows 安装与更新

从 [最新安装器页面](https://github.com/EthanMossvale/AgentWorkbench/releases/latest) 下载 `<版本号>.exe`。这是完整安装包，安装向导支持自选位置；新安装默认使用 `%LOCALAPPDATA%\AgentWorkbenchApp`，已有安装沿用原位置并允许改选。安装后创建桌面和开始菜单快捷方式，无需安装 Git 或 Node.js。

主分支推送经自动构建和部署成功后，已安装的工作台会在启动或后续定时检查时后台下载更新；左下角出现“更新并重启”后点击安装。应用更新从 GitHub Pages 获取，不需要逐版发布 Release。更新保留用户数据，普通退出不会自动安装。当前仅提供 Windows x64，安装器尚未配置代码签名。分发流程和限制见 [文档 38](docs/38-desktop-distribution.md)。

## 运行

开发环境以 Windows 和 Node.js 24 为基线，依赖版本由 `package-lock.json` 固定。在克隆后的项目根目录运行：

```powershell
npm ci
npm run setup:electron
npm run build
npm start
```

Windows 也可以双击 `Start-Dev.cmd`。该入口检查依赖、准备 Electron 并重新构建后启动；仅检查构建可运行 `Start-Dev.cmd --check`。构建失败不会启动旧版本。已有应用使用单实例机制，源码更新后需正常退出并重新启动才能载入新的主进程。

## 功能与状态

- 项目与会话管理、附件、公开运行活动、原生提问/审批和文件阅读。
- 独立双语工作流：输入翻译与发送前预览，公开进度和结果译文；关闭后停止该模块外发并保留历史译文。
- Codex / Claude Code 原生运行时接入，以及独立配置的模型 API 来源。运行时、模型提供方、执行设备、账号和网络出口分别处理。
- SSH 工作空间、设备和原生账号管理；写操作按实际身份、计划和授权执行，未知回执不自动重放。
- 本机 CLI、原生记忆、技能和原生插件管理；记忆交接仅在明确启动接收任务时处理。
- 工作台 ZIP 插件：调用/替换宿主请求、包装服务实现、注册新方法、添加局部界面或替换整个界面。

上述内容是功能入口概览。具体版本、限制、当前实现和验证范围见 [实现与验收记录](docs/16-implementation-status.md) 和各专题；历史通过记录不代表任意连接、最新运行时或第三方插件均已验收。

## 开发与扩展

[开发指南](docs/18-development-and-dependencies.md) · [仓库地图](docs/09-repository-map.md) · [插件 API](docs/36-workbench-plugin-api.md) · [项目规则](AGENTS.md)

所有新增、修改或替换的功能必须提供开发接口，并同步维护插件 API 文档。工作台扩展与原生运行时插件是两套加载机制；含代码的工作台扩展属于经用户批准的完整本机代码权限，不能视为安全沙箱。

```powershell
npm run check:docs
npm run typecheck
npm test
```

完整本地检查入口为 `npm run check`，还会执行构建、隔离桌面验证和依赖审计。涉及原生二进制的测试需准备相应测试运行时；真实模型或远端验收需要独立配置与授权，不属于普通单元测试。
