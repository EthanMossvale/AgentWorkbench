## Storage and release boundary

`packages/ui-preferences/index.ts` defines reviewed product defaults. `ui-preferences.json` is created only in the current user's application data directory, separate from `dist`, the executable, plugin code packages, and chat state. Missing preferences use product defaults; changes belong to that user/device. Normal rebuilds and application updates must not replace the profile. Installers, release archives, and update payloads must never include a developer profile, `build/qa`, acceptance screenshots, secrets, or copied preference files. The release channel/installer is not selected by this change; a future packaging task must verify the final package contents and upgrade behavior.

The version-1 document contains per-key revisions and values, plus a monotonically increasing document revision. Scope is an explicit string encoded together with the preference ID, avoiding delimiter collisions. Updates are serialized by the host; stale revisions are rejected. The renderer coalesces rapid adjustments and drains queued changes through the graceful-quit handshake. Abrupt OS termination can lose a change that has not reached durable storage; this is not claimed as crash-proof storage. Corrupt/unknown files are retained and cannot be overwritten through normal updates. Visible status reports read/write/conflict failures. An incompatible individual value falls back without deleting its raw value.
