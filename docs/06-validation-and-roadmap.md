# 06 · 实验、验收与路线图

> 历史需求/设计基线；现行规则见 [AGENTS.md](../AGENTS.md)，实现与修订见 [文档 16](16-implementation-status.md)。本文旧方案不构成当前部署指令。 [文档导航](README.md)

本文件是后续实现计划。本轮没有运行模型实验、修改网络、部署 worker 或消耗额度。

## 1. 先交付翻译，再验证原生执行与环境保险

**P0先完成独立翻译模块；P1以Claude为主验证原生执行和环境保险，再迁移Codex已有链。** 原生执行目标仍是VPS CLI原生登录/出网，经SSH使用本机手脚；同owner普通文件可跨工作区，系统/设备盘点另行受控。

框架不做SDK登录、不收集两家token；SDK只作参考，E不列替代方案，Generic Agent Harness后排。P0第三方翻译服务是无工具权限组件，并不提前实现通用Agent。后续所有实验使用隔离测试目录/配置，不能接管现有任务或修改共享代理。

### T0 · 独立翻译状态机与原文保护（先于SSH）

使用mock provider/runtime，验证中文输入→英文预览/校验→只提交一次；公开进度可选中文旁注；最终原文/中文双栏。覆盖代码/路径/否定约束保护、产物语言不变、原生事件/签名不变、取消/乱序、输入失败不自动绕过、输出失败不重跑Agent。此阶段无两家登录、无SSH、无模型费用。

### T1 · 第三方翻译真实接入

按明确授权的翻译profile验证协议辅助探测、模型目录、手动覆盖、effort能力、独立密钥、预算/延迟与最小外发。目录请求成功不代表生成/流式/effort均支持。实测翻译质量后再与原生runtime连接；详情见 [13](13-translation-module.md)。

### E0 · VPS profile、投影与owner-wide文件面

在合成/隔离环境验证只读SSH采集白名单、profile版本/过期、声明信息与真实能力分离、自动物化计划。项目A访问同owner目录B成功且不额外审批；系统盘点受独立policy控制；过期/缺字段不回落扫描宿主。原生工具、脚本、hooks/子Agent能否绕过隔离均列入测试，未隔离能力必须标host-exposed。详情见 [14](14-environment-projection.md)。

### G0 · 版本与合规基线

记录两家 CLI/OS 的精确版本、官方分发来源、协议 schema、实验性标志、VPS 原生认证方式、账号所有者与授权范围。不要用“最新版”作为可复现记录。验证框架未读取、导出或保存 token，且未采用 SDK 登录。[S01、S06]

本机 Claude CLI 已更新并核实为 **2.1.281**，桌面为 **2.7032.0**；见 [更新记录](10-local-claude-update.md)。后续固定 VPS 待测版本并记录两端差异。本轮没有部署/更新 VPS，也不将尚未核实的工具委派写成“不可能”或“已支持”。

### G1 · 同机原生对照

在 VPS 原生 runtime 自己所在的隔离测试目录运行一组固定工作：读文件 → 改文件 → 执行测试 → 显示 diff → 看图片 → 恢复会话。该步骤只是核对原生行为的受控对照，不把 R 模式列为首期产品路线；其后在 H 的本机测试目录复现同一契约与结果，再归因跨主机差异。

验收记录包括实际文件哈希/差异、测试输出、工具事件、审批和模型结果。只收到一句“完成”不通过。

### G2 · Codex H 模式

原生实现优先级在Claude之后；已有链的只读分析可并行，不阻塞前置翻译模块。

**这是已有实现的迁移/回归门槛，不是从零可行性门槛。** 先固定旧项目已使用的官方 `exec-server` / deferred executor / `environment/add` / `environments` 组合，在隔离环境复现历史 Windows 原生执行用例，再将其拆出为独立产品模块。已有历史记录见 [原生基线](12-existing-codex-native-baseline.md)。

随后对目标 app-server 版本生成 schema，检查宿主握手、原生工具名称与输入/输出契约、权限、流式事件、取消和恢复。若升级到 Code Mode host 等新接口，另做协议迁移对照；注册 dynamic tools 与原生执行宿主不是等价结论。[S01、L03]

检查范围必须同时含 UI 文件接口与 agent loop 内部工具。`fs/getMetadata` 成功、某个 `command/exec` 转回本机、注册一个 dynamic tool，都不能替代内部 shell / apply patch / image / PTY / 子 Agent 的执行位置证明。

产出逐工具能力表；任何工具仍在远端执行，都要说明用途与权限。不支持的工具默认禁用或清楚标记，不以提示词要求“尽量只用本地工具”作为安全保障。

### G3 · Claude H 模式

这是首个原生执行主线；G编号沿用基线方便引用，不代表先实现Codex。官方SHELL_PREFIX + 文件视图的具体候选与分层验收见 [15](15-claude-native-bridge.md)。

基于本机已更新的 2.1.281，结合其帮助与官方接口继续核实原生执行宿主/工具委派能力；VPS 测试版本和认证方式单独记录。优先追踪原生工具契约及其可公开接入的请求、审批、执行、结果和恢复链，不因已有 Remote Control 行为或前次检索范围而提前判定不可能。[S08–S10]

不修改官方二进制、不通过事后替换工具结果伪造本地执行；自定义 MCP 本地工具不作为默认或降级执行路线。若尚未找到满足原生契约的公开入口，记录“待核实/接口缺口”及证据，继续限定范围研究，不自动换成 SDK、E 或 R。**Codex 通过不抵消 Claude 待验证；两家均须独立达到首期承诺。**

### G4 · H 原生契约与边界联验

分别对两家 H 会话验证：VPS 原生登录且 token 不进入框架；模型请求由 VPS 发出；声明由本机承担的工具确实在本机运行；本机/远端路径、审批、取消、后台任务、子 Agent 与 resume 不发生静默漂移。

断开 SSH 或本地 worker 后，暂停依赖本机的工具并显示真实状态，不改用 VPS 同名文件，不启动本地替代 CLI，不改为 E、本地直连模型或 SDK。E 仅在架构历史比较中记录，本计划不执行 E 对照实验。

## 2. 工具位置测试矩阵

| 用例 | 验证点 | 失败例子 |
|---|---|---|
| 读取/metadata/list | 主机、绝对路径、真实内容一致 | Linux 程序收到 Windows 路径并读错位置 |
| 写文件/patch/rename | 实际文件哈希变更、其他owner/控制面拒绝、失败无半写入 | UI显示diff却改错主机，或误以当前workspace边界拒绝同owner文件 |
| Shell / cwd / env | 实际执行端PID/OS/cwd与必要能力；另标profile来源 | 投影冒充真实宿主检测，或远端执行伪报本地成功 |
| PTY / stdin / cancel | 流式输入、退出码、中断、无孤儿进程 | 只支持一次性短命令 |
| Git / worktree | 正确仓库、脏树保留、并行写策略 | 每个 session 有锁但同一仓库仍互相覆盖 |
| 图片/二进制 | 实际本机资源可见，传输/编码正确 | 只把路径字符串送给模型 |
| MCP / skills / hooks | 归属、权限、执行位置明示 | hooks 在另一端执行敏感命令 |
| 子 Agent / 后台任务 | 不逃逸执行/审批边界 | 主 Agent 本地，子 Agent 默默落到远端 |
| Resume / compaction | 历史、绑定与能力保持，状态变化可见 | 恢复后账号或执行目标改变 |
| 路径与owner边界 | 同owner跨项目可用；中文/UNC/符号链接与真实OS权限 | 用当前workspace根误拒正常文件，或穿透其他租户/控制面 |
| 环境保险 | typed环境查询走VPS profile，执行隔离级别真实 | 仅改文字返回即标强隔离，或快照失败补扫宿主 |

“完全原生”需要选定承诺范围逐项通过；研究样机必须公开未通过项，不能用自定义 MCP 成功、文件面板成功或其他执行模式替代 H 原生工具契约验收。首期发布范围仍以用户确定的两家 VPS 原生 CLI + 本机手脚为准。

## 3. 出口验收：可证明什么

先按类别登记：模型推理、账号登录/刷新、遥测、网页搜索、MCP/插件、工具产生的任意网络。哪些由远端发出、哪些是本地允许直连、哪些被禁用，逐类说明。

证据至少包括：受控请求的本地/远端连接元数据、目标地址/协议、隧道状态、DNS 路径和断线行为；不记录凭据或解密模型 TLS 内容。对本地“直连模型域名”的可观测性有明确边界。

必须测试：VPS 模型连接的 HTTP/SSE、WebSocket（若使用）、重连、DNS 失败、原生账号刷新、远端退出，以及 SSH/本地 worker 断开。连接失败后按实际位置暂停/报错，不转为本地 runtime 或本地模型直出。仅用浏览器查询一次 IP 或本地 TCP connect 成功不构成完整证据。

原生 web search/托管工具可能由服务商基础设施执行，不能谎称它们也必定使用 VPS 公网地址。模型 API 的出站位置与这些远程工具的出口是不同指标。

验收报告只说“所测流量符合指定出口策略”，不说“永不风控/永不验证/永不封禁”。不使用伪造客户端身份或关闭 TLS 校验实现“兼容”。

## 4. 安全与恢复门槛

- workspace 用户直接请求管理 API 仍被拒绝；不能靠 UI 按钮隐藏。
- 设备 A/B 密钥不同；撤销 A 不影响 B；既有 A 会话按已定义策略停止。
- 主机指纹变化阻断；管理员密钥未到达模型环境和日志。
- 本地owner/device归属和动作审批由worker校验；同owner普通跨目录读取不重复批准，注入不能扩大系统盘点/租户/管理权限。
- 单 writer lease、接管失效、事件重放、幂等和未知操作状态全部测试。
- 桌面断网、worker 崩溃、runtime 崩溃、远端重启分别测试，不互相替代。
- 账号能力缺字段显示 unknown；快照过期显示 stale。
- 额度重置一次确认对应一次逻辑请求；不确定结果不重复消费。
- 安装/升级失败可回滚，原有 SSH 登录和无关服务仍健康。
- 对用户现有 1 管理员 + 3 用户级账户做隔离环境的发现/接管测试：重复扫描/重连不创建新账号、不改密钥、不重装 CLI。
- 缺组件时计划只补缺项；并发管理员操作需主机级锁；失败恢复不留下重复账号或错误完成状态。
- 删除重建只涉及选定受管 workspace：其他两个用户环境与管理员 SSH 保持可用；旧设备 grant 不继承新代际权限。
- 环境强保证同时覆盖非典型Shell/脚本/库调用、hooks/子Agent；不能只按关键词判断。文件本身含主机信息时不暗改内容。
- 翻译层无执行权限，不能修改原生签名/审批/环境来源；翻译器重试不重复派发任务。

## 5. 分阶段里程碑

| 阶段 | 内容 | 退出条件 |
|---|---|---|
| D0 / 当前 | v0.2文档、来源、独立Git | 无框架代码/部署，文档相互一致 |
| M0-A / P0 | T0：独立翻译mock与原文保护 | 不依赖SSH或原生登录，状态机/双栏/失败策略通过 |
| M0-B / P0 | T1：真实第三方与可选公开进度译文 | 协议/目录/effort能力如实，质量/费用/隐私通过 |
| M1 / P1 | E0、G0/G1/G3/G4：Claude桥与环境保险 | 原生登录不变，owner-wide可用，真实执行/投影/隔离分别取证 |
| M2 / P1 | G2/G4：Codex原生链迁移与统一桌面 | 不丢已有能力，不把原生链替换成默认MCP或E模式 |
| M3 / P1 | 账号状态/额度、空间发现/接管、设备授权 | 幂等复用、普通用户无管理权、隔离和撤销/重建通过 |
| M4 / P1 | 双主题、模型与翻译设置完善 | 真UI验收；请求值/实际值一致，环境保证标签真实 |
| M5 / P2 | 通用Agent模型与本地模型 | 不与P0翻译服务混同，逐模型测试工具循环/恢复/预算 |
| M6 / P2 | 不互信租户/更多系统 | 对外开放前通过，不替代P1本机信息隔离验收 |
| M7 / P3 | 有损交接与多Agent讨论组 | 身份/预算/可见上下文独立，写入有协调 |

草图与只读研究可并行，但翻译先行，不能被原生桥拖后；安全与能力门槛不能跳过。没有承诺工期；P1明确H和环境保险的已验证范围/缺口，不授权改成其他运行模式。

## 6. 证据记录模板

每次实验记录：日期、版本、模式、provider、认证类型（不含凭据）、runtime/execution/egress 位置、测试目录、用例、预期、观测、文件/进程/网络证据、失败、回滚、未验证项。

结果等级统一使用：文档确认 / 协议验证 / 真实模型任务验证 / 桌面交互验证 / 生产可用性未评估。前一等级不得自动提升到后一等级。
