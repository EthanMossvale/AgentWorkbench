# 20 · VPS 共享账号与原生登录

> 功能与验证专题；事实仅适用于正文注明的版本、日期与验证层级。当前综合状态见 [文档 16](16-implementation-status.md)。 [文档导航](README.md)

## 最新用户决定

- 同一 VPS 使用中央账号目录。管理员一处添加 Codex 账号并完成原生授权后，将账号分配给工作空间；成员能看到获准账号的允许详情，不分别重复授权。
- 每个工作空间独立选择默认账号；空间 A 改选不会改动 B/C。新会话固定当时的账号，旧会话不会跟着默认选择漂移。
- 只有管理员可发起“添加账号”，实际登录由独立的非 root 凭据服务身份运行。成员仅从获准目录独立选择。管理员 SSH 不是模型执行身份。
- Claude 由用户以后手动登录，工作台仅扫描原生状态与允许详情；不实现 Claude 登录、浏览器实时画面或登录态搬运，保留现有浏览器账号。

## 三个独立层次

1. **VPS 共享目录**：持久化服务 authority/generation、账号 opaque ID、身份 generation、允许的邮箱/套餐/观测状态。凭据由远端原生 CLI 在每个账号自己的私有 profile 保管。
2. **工作空间默认选择**：服务端按经过授权的 peer UID/workspace 映射保存，使用 selectionRevision 比较更新。没有全局默认覆盖所有成员，也不在新增账号后自动切换。
3. **会话固定绑定**：新会话用具体 authority/account/generation 构造 `accountRef`；恢复旧会话要保持同一身份。正常 token 更新不等于换账号，撤销或重新登记则需让旧身份明确失效。

账号目录可见、工作空间已选中和原生执行认证成功是三个不同状态。`BridgeEvidence` 的原生认证证据必须绑定同一 `accountRef`，不能把账号 A 的认证证据用于 B。

## 本仓实现范围

- `services/vps-account-broker/`：独立账号服务、Unix peer 身份授权、目录和逐空间 CAS 选择、中心 profile 的原生设备代码登录及取消/租约清理。仅本地合成与协议测试；远端部署需要单独执行已审阅计划。
- `packages/remote-account-catalog/`：经严格 SSH 调用，仅回传允许的目录字段、官方 URL、设备代码与任务状态。服务缺失返回不可用，不回退到每个成员各建 profile 授权。
- 桌面连接页：先读取共享目录，优先选已有账号；管理员新增账号是单独的显式操作，成员没有授权入口。管理员不能替自己保存普通工作空间默认选择。
- 输入区：显示该工作空间的账号选择；会话建立后固定。选择回执不确定时先读取实际状态，禁止自动重放或偷偷换账号。
- 旧 `packages/remote-codex-auth/` 的私有 profile 授权实验保留其测试，但不再是生产桌面的登录路线。不迁移或覆盖既有 `~/.codex`、旧 Broker 或旧账号。

**尚未完成**：新服务的真实 VPS 部署/原生授权、跨工作空间 runtime credential lease 与内存认证桥接，以及完整 H 模型执行。当前目录选择不能被宣称为跨 UID 原生执行已成功，H 提交门禁保持关闭。

## 必须保留的边界

- 登录只由用户显式开始；目录刷新不触发授权，未知状态不等于账号丢失或需要重新登录。
- native token、cookie、SSH 私钥不进入桌面状态、日志、翻译、分享或诊断包。不共用整个 `CODEX_HOME`，成员的配置、历史、会话保持各自独立。
- Broker 独立运行，每个成员请求都重新读取受保护、root 所有的空间策略，按实际 UID、空间启用状态和账号白名单过滤；策略缺失、损坏或空间需恢复时拒绝成员访问。renderer 提供的 role、host ID、workspace ID 不能授予远端权限。
- 授权、目录版本、默认选择、会话绑定分别核对；取消或清理未确认时不能开始新的授权。
- 不自动轮换账号，不为额度/限流自动换用其他账号，也不承诺任何风控结果。

## 已有只读核实

已有工作空间 SSH 的 `--help` 核实 Codex 0.155.1 提供 `login --device-auth`；Claude Code 2.1.273 提供原生 `auth` 入口。旧 Broker 当前不可用，原生未登录状态不能证明旧账号丢失。没有执行真实设备授权、账号迁移或模型回合。官方认证来源见研究记录 S28。
