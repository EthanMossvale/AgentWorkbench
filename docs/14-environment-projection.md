# 14 · VPS 环境识别、自动投影与跨工作区文件访问

> 已退役方案：环境投影与模拟于 2026-09-26 取消。仅保留设计历史，不按本文启用；现行边界见 [AGENTS.md](../AGENTS.md)。 [文档导航](README.md)

设计草案 v0.2。用户将本功能定位为隐私保险方案；本文件只定义架构，尚未采集 VPS、创建虚拟环境、拦截工具或修改本机设置。

## 1. 明确目标与非目标

目标：启用后通过已配置 SSH 只读识别 VPS 环境，自动形成版本化环境视图；模型默认获得该视图，不自行盘点本机所有设备、账户、浏览器或系统信息。**普通文件访问不受当前 workspace 的目录围栏限制。**

约定“模拟”包含两种明确机制：

1. **环境投影**：框架环境查询返回来自 VPS 快照的结构化信息，并标注来源；不是声称这些是对本机做出的真实检测。
2. **环境物化**：在兼容且已授权的本地隔离环境中，按 VPS 的用户态配置建立实际执行环境，尽可能让程序查询到的环境与声明一致。

不把浏览器评分、保证免封或对任意探测完全不可识别作为验收指标。不伪造账号地区、TLS/认证数据、任务成功、文件内容或原生工具结果；不修改官方 CLI 二进制。

本层约束框架提供的工具与实际执行环境，不声称控制供应商未公开的服务端风控或全部遥测，也不修改用户登录浏览器。原生CLI在VPS所见运行环境与经工具取得的本机内容分别取证。

## 2. 四个独立平面

| 平面 | 默认策略 | 不混同的边界 |
|---|---|---|
| File Plane | `owner-wide`：同一所有者、已授权设备上，遵循 OS 权限跨目录访问普通文件 | 当前 workspace 是组织/cwd，不是安全围栏 |
| Inventory Plane | 自动广泛设备/系统盘点受控；环境查询优先走 VPS 投影 | 文件权限不自动授予硬件、账户、网络和浏览器信息普查 |
| Execution Plane | 强隔离模式在真实隔离环境运行；必要宿主能力经单独明确的 worker 提供 | 执行能力必须真实，不能被 VPS 快照覆盖 |
| Management Plane | 管理员创建空间、管理密钥/设备和策略 | 不向模型开放，不因跨工作区文件权限而增权 |

允许从项目 A 读取项目 B、下载目录、资源目录或其他普通目录，不额外弹“越过工作区”。写入、删除、发布等仍遵循已有动作审批与 OS 权限，不因换目录新增一道 workspace 审批。

同一人的多个项目不等于其他租户。其他用户的数据、框架控制面与管理密钥不进入 owner-wide 文件服务。新设备仍需要 DeviceGrant；本功能不自动扫描局域网并取得全部设备访问权。

## 3. SSH 识别与 RemoteEnvironmentProfile

启用保险功能时批准采集字段与刷新策略；后续在范围内自动完成，不让模型生成临时管理员探测命令。优先使用普通 workspace 身份；管理员连接只做确有必要的管理动作。

允许采集的默认范围：OS/发行版与版本、架构、shell 及路径语义、locale、时区、原生 CLI 和指定任务依赖的版本。仅按兼容性需要读取粗粒度能力，不默认收集机器序列号、MAC、machine-id、所有用户/进程、全部安装包、全部环境变量或凭据。

快照字段至少包含：

- `profileId`、`sourceHostId`、`workspaceOwnerId`、`profileVersion`。
- `observedAt`、`validUntil`、采集器版本和允许字段集合。
- 每个字段的 `value`、`status`、来源类别与置信度；状态为 known / stale / unknown / unsupported。
- `runtimeFacts`、`targetUserland`、`pathSemantics` 与 `capabilityConstraints`，避免把意图配置与观测值混写。

SSH 主机指纹变化先阻断信任，不自动重新采集后接受。首次启用、连接目标改变及过期时按策略刷新；普通重连可复用有效快照，不持续进行全机扫描。探测结果按结构化数据校验、限制长度，不作为 shell 或高权限指令执行。

采集失败或缺字段时返回 unknown/stale，不改为扫描本机“补齐”。没有相应数据就不编造远端数值。

## 4. 模型看到什么

框架提供的环境视图可以包含：VPS 原生 runtime 信息、投影环境信息、已授权文件命名空间，以及完成任务所必需的执行能力。响应带 `source=remote-profile`、profile 版本与观测时间，使用者可查看详细来源。

同一会话绑定同一个 profile 版本。刷新产生新版本，回合边界检查后生效；执行中不悄悄把 Linux/Windows、路径规则或工具链切换掉。

模型请求自动全设备盘点时，策略先判定为 Inventory 操作：若属于已批准的环境字段，返回投影；否则拒绝自动盘点或请求独立授权。不要实际扫描宿主后再把结果替换成 VPS 值，这既已经产生了隐私访问，也会破坏审计。

协议尚未暴露环境查询入口的原生 CLI，不能仅靠新增一个说明工具完成这项保证；必须继续验证它的内建 shell、文件工具、hooks、子 Agent 和后台任务是否经过真正的执行边界。

## 5. 自动物化与兼容性

拟定 `EnvironmentMaterializer` 根据 profile 生成兼容计划：用户态发行版、shell、locale/时区、必要依赖与逻辑路径视图。只有用户事先批准的镜像/依赖策略内才自动建立或更新；不得为了匹配 VPS 而全局改本机时区、语言、字体、系统账户或网络设置。

优先在本地 VM 等真实隔离环境中运行通用原生工具，再通过文件服务访问 owner-wide 数据。容器可作为较轻隔离选项，但不能宣传为独立内核或与 VM 同等边界。无法物化的字段标记差异，不能伪称克隆了 CPU、内核、机器身份或公网地址。

文件服务不只挂当前项目：按已授权所有者命名空间按需解析跨目录路径，保留 host/device 身份、权限和真实目标。可按卷/路径提供稳定映射，不能每换一个 workspace 都重新要求文件授权。若某路径技术上不可映射，应显示“执行端不可达/不支持”，不是伪造“越过 workspace 被拒绝”。

本机 Windows、Blender、GPU 或设备能力需要独立 `ExecutionCapabilities`。VPS 有某程序不表示本机有；本机只能运行 Windows 工具时，不向模型伪报它接受 Linux 参数。模型可得到完成任务所需的最低真实能力信息，避免以隐藏环境为由破坏正常工作。

## 6. 保证等级

| 状态 | 可交付的保证 | 必须显示的限制 |
|---|---|---|
| `projected` | 框架环境接口使用 VPS profile；不主动自动盘点宿主 | 只有投影，没有验证所有本机执行边界 |
| `isolated` | 所承诺工具在真实隔离环境中，系统查询针对该环境；文件通过独立服务访问 | 按工具列出覆盖范围，不承诺完全不可识别 |
| `host-exposed` | 明确允许必要宿主原生能力，普通文件仍 owner-wide | 任意未隔离 Shell/Python/插件可能读取宿主信息，不能承诺全面阻止 |

不允许仅因勾选“环境保险”就显示 isolated。若宿主 Blender 或某原生工具允许任意 Python/扩展执行，它可能重新暴露宿主环境；应在能力清单中降级或另行隔离，不能只靠命令名黑名单包装成强保证。

提供广泛文件访问与隔离执行可以并存；提供宿主机任意未隔离代码执行，与保证模型不能查询任何宿主信息不能同时成立。系统调用/进程/文件服务边界才是强限制的依据，提示词和关键词分类不是完整沙箱。[S24]

## 7. 不暗改文件、执行结果或权限

用户文件、源码、构建日志可能本来就含电脑名、中文、路径或硬件信息。跨目录文件照原文返回，不为了投影悄悄替换内容；环境视图只影响明确的环境查询接口。

如果用户希望连这些文件中的信息也不外发，需另行选择可见的脱敏/排除规则；默认不得以保护环境为由篡改调试证据或模型要编辑的文件。

原始 stdout/stderr、退出码、diff、文件哈希保留；不能把任意 `uname`/PowerShell 命令成功后的输出伪装成另一台机器。强模式应让命令真实运行在合适的隔离环境，而不是事后改输出。

Inventory 权限按信息类别、目的与 scope 判断，不按“命令在项目目录内”放行，也不因访问项目外文件拒绝。模型文本、翻译文本、仓库说明与工具返回不能扩大 policy 或签发授权。

## 8. 组件与关系

```text
已授权 SSH → Remote Profile Collector → Profile Store
                                       ├─ Environment Projection API
                                       └─ Materialization Plan → Isolated Executor

原生 CLI 请求 → Execution Broker
               ├─ 普通文件 → Owner File Service → 同 owner 多目录/多项目
               ├─ 环境查询 → Projection API → 带来源的 VPS profile
               ├─ 隔离执行 → Isolated Executor
               └─ 宿主专用能力 → 明确授权的 Host Worker + 实际能力标签
```

`EnvironmentPolicy`、`FileAccessPolicy`、`ExecutionBinding`、`DeviceGrant` 分别持久化；UI 展示实际保证等级、profile 来源/时间与执行位置。原生 CLI 在 VPS 的认证与模型请求不受该投影层接管，翻译模块也无权更改这些权限。

## 9. 验收与反例

| 用例 | 预期 |
|---|---|
| 项目 A 读取/搜索项目 B 的正常文件 | 成功；不因 workspace 边界重复审批 |
| 允许的普通路径含中文、空格、UNC、符号链接 | 真实路径与权限正确，原始内容不变 |
| 项目内脚本请求全机设备/账户/网络盘点 | 不因位于项目内就放行；按 Inventory 权限处理 |
| 框架环境查询 | 返回指定 profile、来源/时间和版本；不调用本机补扫 |
| SSH 断开、profile 过期、字段缺失 | 返回 stale/unknown；已允许文件访问不被无故收回 |
| 原生 Shell 换成 Python/系统 API/子 Agent 发起探测 | 隔离保证仍成立，否则必须标 host-exposed，不能称完全阻止 |
| 本机没有 VPS 所有的程序/GPU | 正确报告实际执行能力差异，不伪造任务成功 |
| 原文件包含电脑名或系统信息 | 哈希、内容保持原样；投影不篡改文件 |
| 访问其他租户、管理密钥或未授权设备 | 拒绝；owner-wide 不跨越这些独立权限边界 |
| profile 刷新、会话恢复、多个设备并行 | 版本/设备绑定明确，无信息串用或静默改变执行端 |

基础 profile/投影约 3/5；owner-wide 文件服务与原生工具联动约 4/5；完整隔离、宿主专用能力和防旁路验收约 5/5。均为规划判断，当前没有实现或验收声明。
