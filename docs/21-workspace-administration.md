# VPS 管理员、工作空间与设备

> 功能与验证专题；事实仅适用于正文注明的版本、日期与验证层级。当前综合状态见 [文档 16](16-implementation-status.md)。 [文档导航](README.md)

本轮按用户确认的层级实现：**VPS 管理员入口 → 多个成员工作空间 → 各空间的设备授权**。管理员入口只用于管理；本机也必须选择成员工作空间才能创建原生任务。输入区不列出管理员，可信主进程再次拒绝管理员或误标为成员的 root 身份。离线示例不连接 VPS。

## 2026-09-27 UTC：连接、设备与删除交互（U103，覆盖下文旧语义）

新连接默认管理员 / root，使用分段角色按钮。选择密钥通过本机文件浏览器，确认连接时复制原始字节到 `~/.ssh/agent-workbench/<selection-id>/identity`；原文件与已有密钥不变。Windows 当前用户拥有副本完整控制，其他普通用户不继承读取权；这只是本机文件保管，不降级服务器登录身份或远端权限。取消添加不复制。当前支持 OpenSSH 密钥文件，密码、带口令密钥和 PuTTY PPK 尚未适配。

单独私钥不作为服务器地址配置读取；IP、端口和真实服务器用户名来自服务商或管理员。可导入 OpenSSH 配置中明确的 Host/HostName/Port/User/IdentityFile/UserKnownHostsFile 字段并自动填写，其余指令、通配符与多别名拒绝，不执行 ProxyCommand、Include、Match 等内容。root 为 Linux 管理员账号，连接名称才是本机可自定义的备注。首次连接展示主机指纹，由用户与独立可信来源核对后保存 known_hosts，再验证用户名和 UID；不会关闭严格主机校验。

左侧同时显示远端受管空间和已保存的本机成员连接，不再只列出后者。目录可折叠，成员按同端点用户名去重；整个连接卡片都可选中，小眼睛独立遮盖/显示 IP，地址区域不可选择复制。空间列表可展开/折叠，启用开关复用技能页组件，仍执行服务端计划与确认。

连接到本机或导入成功立即设为新任务的默认空间；“当前默认空间”与“用于新任务”区分现有授权和任务选择。已连接本机仍可用同一服务器的管理员继续导出新文件。管理员和成员的连接详情都提供移除：只清理本机连接/选择/缓存，不动远端空间、密钥或历史；处理中或结果未知的任务阻止移除。

导出 `.awworkspace` 供一台设备成功导入一次。原文件、复制件和重启后的已完成记录都不能再授权，提示“文件已失效，请向管理员重新获取。”。回执未确认时允许恢复同一个未完成登记，复用原密钥；它不是成功后重复导入的例外。导出文件含本次新建的受限 bootstrap 能力，不含管理员或原设备私钥；不是空间文件/历史的备份。受管导出绑定真实管理身份与空间 ID；同名空间重建后不能消费旧空间能力。

修复新建成员 HOME 没有 `.ssh/authorized_keys` 时的本机连接失败，并修复 22 端口主机记录格式与导入预览/返回身份不一致。管理列表读取 `aw-device` 公钥标记中的设备名，可精确踢出选定设备；共享锁和原子替换保护其他已有授权。列表表示授权登记，尚未采集实时在线状态；踢出阻止后续 SSH 登录，不宣称强行关闭已建立会话。

**停用保留原设备授权，重新启用恢复同一公钥，无需重新导入。** 被明确踢出的设备不恢复；未使用的导出能力在停用时失效。删除并重新创建才产生新空间身份，旧设备与文件不能转用。删除成功直接从页面和本机连接目录消失，只给短提示，不显示已删除列表、重建入口或常驻删除结果；内部防重放状态不作为界面记录展示。

验证边界：本轮仅源码、合成协议、隐藏独立 Electron 和 WSL 临时目录验证；没有修改真实 VPS、实际 SSH 用户、原私钥或用户正在使用的窗口。此前段落的真实 VPS 验收仅属于当时版本，不能证明本次更新已部署。

## 2026-09-26 最新删除与共享身份边界（U94）

管理员页面自动读取所属工作空间。删除操作现在永久销毁普通成员的整个 `/home/<username>`（含缓存和 SSH 公钥）、系统用户及设备/邀请/账号使用权；预览显示范围和磁盘占用，必须输入用户名确认。只支持核实的标准 HOME，目录外文件不在递归删除范围内；挂载、符号链接替换、身份变化或保留用户会阻止操作。只有确认销毁回执才显示成功，断连或部分失败保留限制并查询结果，不重复执行。重建生成新目录、代次和设备 SSH 授权，不恢复旧数据。本机历史和用户提供的私钥文件不随远端空间删除。

三个历史身份 `member-a/member-b/member-c` 是用户本次明确指定的例外：实际数据和 HOME 已删除，Linux 身份继续用于 sing-box；公钥集中在 root 管理的 `/etc/ssh/authorized_keys.d/`。匹配配置只改变这三个用户的公钥查找位置，客户端用户名/密钥不变。它们被标记为 SSH 专用，不能从工作台纳入、删除或复用名称。实际验证了 root/PC1 原密钥新连接与 PC1 转发；PC2/PC3 只核对公钥、用户与配置。详细执行与证据见 `16-implementation-status.md` 的 U94。

CLI 与登录仍共用：每家一份受保护共享安装，每个账号一处专用原生登录配置，由管理员集中管理；空间只持有使用权和自身文件，不逐空间安装/登录。真实 VPS 的统一账号服务尚未安装，本轮只清理旧空间并迁移 SSH 公钥，没有执行该部署或模型登录。U82/U92 已取代下文历史旧 broker 和逐空间 Claude 登录说明；U94 已取代“移除保留用户文件”的说明。

## 2026-09-26 早期管理方式（U70–U73，历史记录）

管理区域现在通过已有管理员 SSH 按需执行，不要求先安装管理常驻服务或 HTTPS 前端。启用账号配给时另建本机共享额度 socket，见下文。若已经有管理 socket，则继续使用该权威服务；不会在服务异常时私建第二套注册表。未初始化的列表读取不写远端；第一次明确预览创建本项目的私有日志目录 `/var/lib/agent-workbench-ssh-control`。配置应用发布 `/var/lib/agent-workbench-policy/workspaces.json`，记录暂停/删除的拒绝状态，使工作台账号入口和下一次原生 turn 不能回退到旧默认账号。此策略不接管旧客户端本身的授权。

列表刷新同时识别既有空间，逐行纳入优先；新建、配置、暂停、移除均经过具体预览和确认。移除保留系统用户及文件。空间可直接导出 SSH 邀请或连接到本机；已有本机连接先验证并复用。SSH邀请和本机连接仍使用原 portable 设备登记机制，其密钥未混入 HTTPS 管理服务的设备撤销列表，界面明确区分。新建普通系统成员不会自动修改旧 broker 的允许用户表，不会安装 CLI 或取得新原生执行验收资格。

共享账号区域分 Codex/Claude 页签。Codex 使用权按工作空间紧凑逐行保存，保留版本校验。Claude 显示各空间原生登录状态和登录命令；无已登录账号也有完整空状态。原有“读取环境”和连接详情的“识别已有空间”按钮均移除，host/probe 不再是可调用 IPC。

### 额度与重置卡

当前已接入既有 Codex broker 配合固定 0.155.1 原生运行时的账号额度 API：按原生池显示百分比、窗口和重置时间，额外额度保留原生单位，不换算为 USD。随额度读取返回重置卡总数、明细和到期时间；null 是未知，0 是明确无可用卡。不会为了读取别的账号去切换成员当前账号；尚未被已登记成员选中的账号会明确提示。

用户逐次确认后才调用原生 reset-credit consume。确认记录保存在桌面自己的私有数据目录，绑定 SSH 身份、账号代次、卡片和 UUID；提交前落盘，重开后可恢复未确认请求。超时后再次确认复用同一 idempotencyKey，不生成新兑换；原生 alreadyRedeemed 不重复消费，nothingToReset/noCredit 不标记成功。没有执行真实兑换测试，也不会自动消费卡片、购买额度或绕过限流切账号。

配给以**每个账号完整周窗口的百分比**为单位，字段就在对应账号旁；只有原生读取确实返回 5 小时窗口时才另列 5 小时比例。三台设备对应的三个空间各配 33%，合计 99%，余 1%；第二账号单独算 100%。留空是未配给，0% 是零配给；暂停保留预留，删除释放。按账号、按窗口分别校验合计不超过 100%，变更仍有 CAS 预览确认。旧月度 USD 字段只作为兼容元数据保留，不显示、不自动折算。

每个账号独立提供「允许超限使用」，默认开启。空间自身份额耗尽后，优先向余额最多的其他活跃空间借用，再使用未分配余量；记录借方、原出借方和窗口。在**该窗口下一次已确认刷新**时，先从借方新配给归还给原出借方，不足部分结转，不跨账号或周/5小时窗口抵销。已开始窗口的比例修改下次刷新生效，超限开关立即生效。关闭后不产生获准借款，下一回合前检查剩余配给；已发生的超出消费仍如实记为超额，不伪造回滚。

多个设备通过 VPS 上同一个 Unix socket 账本记账，端点为 `/var/lib/agent-workbench-policy/quota.sock`，没有新增网络监听端口。首次确认应用配给时按需安装本项目的 root-owned Python 组件；已配置后管理员刷新可在 VPS 重启后重新拉起。成员只用自身 SSH 密钥，服务依据内核 peer UID 绑定空间；成员上报的百分比/刷新时间被丢弃，改由可信 helper 在对应成员 UID 下读取原生账号额度。私有凭据不传回桌面。服务源码、注释、固定消息和日志均为英文，中文预览在桌面生成。当前本轮**没有部署到真实 VPS**。

账本只接收已绑定原生回合的数值 token 通知，累计游标去重；多条通知累加，断线先落盘待同步数值记录，再使用原作用域重试。并行已知生产者结束后一起按观测 token 比例分摊共享额度变化，过期租约及无法归属变化保留为未归属。达到至少 2 个百分点的有效样本后，估算完整窗口 token = 同段观测 token × 100 / 原生额度增量；不是固定官方汇率，模型组合和未观测客户端会影响准确性。

界面展示估算余额、原出借方债务和刷新偿还记录。覆盖范围是工作台已观测根会话活动；未证明覆盖所有原生客户端或独立子 Agent 消耗。检查发生于下一回合之前，一次正在运行的请求可能超出配给，不能宣称厂商侧原子预留或防旁路硬限制。Claude 的管理界面保留完整空状态，但无已验证额度/重置卡适配时仍显示未知，不伪造数据。

以下保留原常驻服务/HTTPS 的详细协议说明；涉及“尚未部署”的描述仅指该可选部署方式，不表示当前 SSH 管理通路不可用。

## 2026-09-26 已有 VPS 的直接接入

SSH 页负责选择本机工作空间。选中成员后只核实 SSH 用户与 UID、读取公开账号目录并保存选择；不再采集环境 profile，也不向模型投影 VPS 环境。本机执行器返回的真实 Windows 环境就是工具使用的环境；原生运行时与模型网络仍在 VPS。已有任务的工作空间绑定不随新选择漂移。

针对已安装的 `/run/codex-device-auth/broker.sock`，工作台提供公开目录兼容层。root 使用登记成员的 peer 身份读取公开目录；管理员页可将账号分配给登记的成员，策略保存于 root 管理的 `/var/lib/agent-workbench-existing-accounts/grants.json`，以 revision 防止覆盖并发变更。成员只显示获分配账号，没有策略时保留已有默认账号。此策略控制本工作台入口；旧客户端本身的授权仍由旧服务管理。兼容层只调用 list/select，不读 token、不刷新账号、不提供重复授权。

页面顶部“导出工作空间”可直接选择已存在成员并由同 VPS 管理员授权，不依赖下面尚未部署的 HTTPS 控制服务。新的 SSH 型 `.awworkspace` 含 1 小时、仅可登记一次的受限 bootstrap 密钥；该新密钥只能执行固定登记命令，不能打开 shell 或转发端口。接收设备生成自己的 Ed25519 密钥，远端将邀请授权原子替换成该设备公钥，再严格验证主机与成员 UID。文件不包含管理员私钥、既有设备私钥或模型 token。它是连接邀请，不是工作空间文件内容、历史或系统配置的备份。

此处原“同设备成功后再次导入”和“SSH 设备不进入管理清单”行为已由 U103 覆盖：成功一次即失效，只恢复未完成登记；SSH 型设备纳入名称展示与精确撤销。导出会新增本次邀请的成员 SSH 公钥授权；以下“所有修改经过计划”特指新控制服务的 CRUD 流程。SSH 型导出通过弹窗的目标选择和文件保存明确触发。

真实 VPS 验证已完成导出、新密钥 SSH 登录、同设备恢复、其它设备重放拒绝；已移除本次测试公钥并核实原 `authorized_keys` 哈希不变。模型请求为 0。新 HTTPS 控制服务、账号跨 UID 的模型执行和完整 H 链仍须另行验收。下文保留控制服务协议与历史阶段说明，不能将其未部署状态解释为新 SSH 导出不可用。

## 管理工作流

连接页使用紧凑的 VPS／成员列表；右侧管理员分为“工作空间、共享账号、连接详情”，成员只有“可用账号、连接详情”。默认不铺开 SSH 路径、账号认证字段、环境及设备列表。配置空间和邀请设备保留为常用操作，暂停／移除放入“更多操作”；这些入口仍须核对具体计划并确认。页签切换只改变展示，不自动触发远端请求；正在读取或应用的状态继续保留。

连接页面将同一主机、端口和本地所有者下的工作空间放在管理员入口下面。此分组只是导航，不授予权限。所有管理请求仍经保存的 SSH 身份、严格主机校验和固定 Unix socket 发送；控制服务通过 Linux `SO_PEERCRED` 核实 UID 0。

添加管理员后先只读识别已有用户和工作空间。复用已有空间使用 `workspace/adopt`，只有明确选择创建才执行 `workspace/create`，不能自动按固定数量重建系统用户。管理员可配置名称、工作目录、允许的运行时、限定环境变量、账号列表和逐账号周/5小时百分比配给。

所有远端修改都经过 `workspace/plan` 的具体效果预览和 `workspace/apply` 的确认，绑定服务身份、部署代次、配置版本、计划摘要和有效期。每个计划只提交一次，操作 ID 与计划 ID 相同；回执不确定时只能读取实际状态，不能自动重放。

停用空间关闭工作台账号访问和未使用导出能力，并暂时移除本服务登记的公钥；保留授权记录，启用时恢复原密钥。删除行为按 U94 永久销毁已核实的成员用户和 HOME；成功后按 U103 从界面消失。既有非本服务公钥不由停用/单设备踢出操作修改，已经建立的 SSH 连接也不被冒称已关闭。

## 账号与配给

Codex 由管理员集中发起原生设备代码授权。成员目录每次按可信策略文件的实际 UID、空间状态及 `allowedAccountIds` 过滤；未配置、损坏或停用的策略拒绝访问。没有凭据导出端点。管理员不设置自己的工作默认账号，成员在获准账号中独立选择，新选择只影响新会话。

Claude 仍由用户手动登录，现有只读发现展示其公开账号状态。没有实现浏览器辅助登录、会话搬运或 token 复制。当前中央原生授权及账号目录实现针对 Codex；不能把它表述为 Claude 共享运行已经完成。

配给与借还属于工作台估算账本，原生厂商额度是来源。保存百分比不是厂商账号之间划转额度，也不是为任意客户端执行硬限额。原生执行资格继续按各连接独立验收；环境策略不自动安装 CLI、改系统软件或声称已物化隔离环境。

## 导出与导入

管理员为一个空间创建限时、一次性的邀请，保存为 `.awworkspace` 文件。文件含空间标识、公开 SSH 端点、主机公钥、HTTPS 登记入口与邀请秘密；**不含管理员私钥、已有设备私钥或模型账号凭据**。邀请秘密在桌面主进程内处理，不进入 renderer、普通应用状态、剪贴板或日志。

其他设备导入时先显示目标 VPS、空间和有效期；用户确认后，由本机 OpenSSH 自动生成独立 Ed25519 设备密钥，通过 HTTPS 仅提交公钥，然后用邀请中的主机公钥创建独立 `known_hosts`。只有严格核实成员 SSH 身份后才登记可用连接，不需要手填密钥路径。私钥留在当前设备的应用数据目录，不进入邀请文件或上传服务端。

每次导出用于一个新设备。重复导入同一邀请恢复同一个本机密钥及导入记录；服务端同邀请、同公钥可幂等回读，不能换公钥重复使用。只有主进程核实已存在匹配的本机登记记录及原公钥时，过期邀请才显示“恢复此设备连接”；新设备仍不能使用过期邀请。管理员可逐设备撤销工作台登记的公钥。导入失败会保留本次新生成的密钥供恢复，并明确告知授权回执是否已确认。

控制服务的登记 HTTP 监听仅面向本机回环地址，未来部署必须提供经过验证的 HTTPS 前端；桌面拒绝明文 HTTP、重定向和不匹配的身份回执。构建桌面程序不会部署任何服务或开放端口。

## 托盘

点窗口 X 隐藏同一个窗口，草稿和 renderer 继续存在；点击托盘恢复。托盘“退出”才关闭新请求入口，等待正在发起的授权与清理流程，然后真正退出。托盘创建失败则回退为正常关窗退出，避免出现无法找回的后台进程。休眠、系统强杀和远端失联仍依赖远端授权租约，不能据本机退出声称已确认远端清理。
