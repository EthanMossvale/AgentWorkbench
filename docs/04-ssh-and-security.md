# 04 · SSH、工作空间与本地执行安全

> 历史需求/设计基线；现行规则见 [AGENTS.md](../AGENTS.md)，实现与修订见 [文档 16](16-implementation-status.md)。本文旧方案不构成当前部署指令。 [文档导航](README.md)

v0.2：文件访问与系统信息控制分层。以 [环境保险设计](14-environment-projection.md) 为准；同owner的跨工作区普通文件不以项目边界拦截。

## 1. 管理面与运行面

管理员 SSH 只用于主机引导、创建/维护工作空间和管理授权。模型、普通 workspace 以及前端 renderer 都不能得到管理员私钥、通用 sudo 或管理 socket。

管理面建议使用受限 broker：固定动作、结构化参数、服务端授权、审计和可回滚结果。不要让模型拼接 root shell 命令执行“创建用户”。是否安装系统服务、修改 SSH 或防火墙必须独立授权；本轮不做这些操作。

按用户提供的信息，当前 VPS 已有 1 个管理员账户与 3 个用户级账户；本轮未连接核实。首次输入管理员 SSH 后先自动只读发现并给出接管/复用清单，缺少的组件才进入创建计划，不能每次连接都新建用户。详见 [发现与接管](11-workspace-discovery.md)。

普通用户“不能再生成工作空间”的定义：不能创建**平台受管工作空间**、新系统身份、其他人的授权或提升权限。这由服务端实现，不只是隐藏按钮。

保留任意 shell + 网络访问时，不能保证用户绝不转授访问或自建服务。OpenSSH 文档亦提醒禁止 forwarding 并不足以限制拥有 shell 的用户自建转发。[S18]

## 2. 分发工作空间，而非复制管理员 SSH

建议对象关系：`Host → Principal/Tenant → Workspace → DeviceGrant`。

推荐导入流程：

1. 新设备本地生成独立密钥，只提供公钥/公钥指纹。
2. 管理员选择已有 workspace 或创建新 workspace，并登记该设备授权。
3. 导出连接描述：服务器/端口、可信主机指纹、workspace ID、设备授权 ID、权限和有效期。
4. 设备导入描述，验证与自己的私钥匹配；私钥不随普通分享包传播。
5. 连接后服务端再次校验 workspace 状态与设备授权。

P1 的 SSH 接入阶段可人工批准公钥；一次性邀请和短期证书后续实现。确需管理员预生成设备私钥的兼容方式应单独定义安全交付、首次换钥和销毁，不能作为默认“复制给任何人”的便利功能。

同一人多设备可选择访问同一个 workspace；不同用户默认独立 workspace 和模型登录。设备级私有工作空间也可支持，但设备不天然等于租户。管理员可管理基础设施，不应在 UI 中获得“一键导出全部模型 token”。

授权登记的权威存储由管理面持有；不能让普通用户自行编辑受信授权列表就获得平台新增设备权限。[S18]

“搜寻密钥”默认指公钥授权、指纹与设备绑定记录，不搜集/导出管理员或其他设备的私钥。已有私钥留原设备；新设备不能从服务器公钥恢复私钥，缺少访问凭据时单独登记新设备授权。

删除重建是独立高风险动作：显示精确工作空间、受影响设备/任务与数据，冻结写入，按选择备份，撤销旧授权，再创建新代际并验证。未知归属、系统用户、其他项目目录不得进入自动清理列表。

## 3. 隔离等级必须公开

| 等级 | 建议实现 | 可承诺范围 |
|---|---|---|
| Trusted | 独立 UID、HOME、runtime config/history、文件权限 | 可信个人/小团队；不同目录本身不算隔离 |
| Isolated | 受控容器、最小能力、网络/资源/挂载策略、隔离测试 | 不互信用户开放之前的候选门槛，不是自动安全证明 |
| Strong | 独立 VM/microVM 或独立主机 | 更强租户边界；更高资源与运维成本 |

Docker daemon socket、可写特权脚本和宿主敏感挂载不能交给普通 workspace。容器共用内核等边界需纳入风险模型。CPU/内存/PID/IO 预算与磁盘容量配额分别设计。[S19–S20]

原生满血表示在获授权环境中保留工具能力。普通文件可在同owner已授权设备上跨工作区、跨目录访问，仍不等于root、跨租户读取或自动全设备盘点；这些是不同授权维度。

## 4. 远端运行时操作本机的额外边界

本地 worker 是独立执行主体。文件授权采用 owner-wide：同一所有者的普通目录属于已授权文件面，不因离开当前项目而重新批准。新增设备、系统盘点、管理员操作和原本需确认的敏感动作另行授权；不得把“跨workspace读文件”误分类为增权。

每项请求至少绑定：session、device、workspace、operation ID、工具/参数摘要、目标 OS/cwd、grant、lease/fencing token、过期时间。网络已加密不等于操作已被授权。

审批绑定具体参数与目标；被批准的 `read` 不能偷换成 `write`，旧 session 的批准不能复用到新主机。内容发生变化后应重新判断批准是否仍有效。

模型、仓库文件、网页、终端输出、MCP结果和译文均不是管理员授权。它们不能扩大owner/device/系统盘点权限，也不能把远端路径解释为另一台机器的同名目录；同owner跨项目文件读取不属于这种权限扩大。

有任意 shell 权限时，字符串检查不是可靠沙箱。受限模式必须由 OS/进程权限或受控执行环境落实；无法强制的权限必须在 UI 明示，不能给出虚假的路径隔离保证。

环境保险优先通过SSH获取最小VPS profile，环境查询返回来源明确的投影；有强要求时用真实隔离执行环境并通过独立文件服务保留跨目录访问。未隔离宿主Shell/Python/插件只能标记host-exposed，不承诺拦住一切设备探测。不实际扫描后再伪造输出，也不为投影改写用户文件。

## 5. 网络与身份

- 首次连接验证主机密钥；变化默认阻断，不能全局关闭 host-key 检查。[S18]
- 默认不启用 SSH agent forwarding；需要时明确解释风险与范围。[S18]
- 数据通道、工具通道、管理通道分别授权；不向公网开放未认证 broker/app-server。
- 桌面主动建立出站 SSH 通道；如需反向工具连接，限定为隧道内/回环端点，不要求开放本机公网端口。
- 模型请求仍使用原始目标的 TLS；首版不做解密中间人，也不通过改写模型请求来模拟官方产品。
- “固定出口”只描述被验证的流量类别；模型 API、OAuth、MCP、web search、插件、工具网络需分别列策略。
- 指定远端出口失效时暂停/报错；不得静默直连。不能保证因此永不触发供应商的验证或限制。

## 6. 断线、撤销与多设备

会话事件按序持久化与重放；每个会话单 writer，明确接管。发命令和收到结果之间断线时，先查询 operation 状态；不自动重放不确定副作用。

撤销动作分别定义：阻止新登录、关闭已有连接、停止平台任务、取消本地授权、保留或删除数据。吊销 SSH key 不自动等于终止所有在途进程。[S18]

H 模式本机离线时不能切换执行目标；所有依赖该本机的工具等待、取消或失败。恢复后重验设备身份、路径与 lease，不能只根据相同电脑名称续接。

多 session 同时写项目时采用独立 Git worktree 或明确串行策略；外部 SSH/其他程序仍可能修改文件，补丁应用需检测基线变化。

## 7. 密钥与账号

不同 owner 的 CLI HOME、配置、历史和凭据分离；不自动复制管理员登录给新用户。自己同一账号跨设备使用也需符合供应商规则，不假设任意共享合法。

拥有同一 OS 身份任意 shell 的程序可能触及该身份运行时所需的凭据，因此不能承诺模型永远看不到自身凭据；通过最小环境、分离账号服务、授权边界与脱敏降低暴露，且不能破坏原生认证条款。

首期两家账号均在 VPS 的原生 CLI 中完成官方登录，认证由远端 CLI 自行管理；本地框架只保存账号展示元数据与绑定 ID，不做 SDK 登录，不提取/同步订阅 token。Codex 即使公开某种 token 接口，也不等于本项目应当采用账号令牌池，更不能套用于其他供应商。[S01、S06]

日志不含 SSH 私钥、API key、OAuth callback query、完整 auth URL、认证文件或未授权会话内容。诊断包默认脱敏；“本地 token 用量统计”不需要收集凭据。

## 8. 发布前安全验收摘要

至少证明：普通workspace不能调用管理动作；同owner跨项目文件读取可用而不同租户数据仍隔离；设备独立撤销；主机指纹变化阻断；环境快照失效不补扫宿主；系统盘点不能借普通文件授权自动放行；断线不重复副作用；安装回滚后原有SSH和服务仍可用。

更完整的用例与失败判定见 [验证计划](06-validation-and-roadmap.md)。
