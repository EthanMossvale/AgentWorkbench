## 共享什么，保留什么

2026-09-26 U93：共享 CLI 准备可在明确确认后下载固定版本的官方发布包。预览不下载，原 root 私有或成员可修改的安装只作诊断，不自动放宽权限；独立共享安装位于 `/opt/agent-workbench/native/`，以固定 SHA256、大小、受保护目录和版本自检约束。CLI 安装与原生认证仍是不同步骤，不复制登录配置。缺少 CLI 不再只能提示用户自行安装；未知安装回执必须重新检查。已有服务的自动升级仍不在此流程范围。

2026-09-26 接入修复：账号页不再根据空间发现结果回退为逐空间登录。默认账号目录只将 `native-owner` 用作认证和运行入口；旧 Codex 的公开信息另存于只读 `legacy` 项，服务不可用时仍可显示待接入账号，不放进可选账号列表、不用于执行或额度降级。管理员从同一账号页预览并明确确认统一服务准备，再接入原账号；工作空间只领取使用权。服务准备和原账号登记是两个明确操作，准备本身不登录、不读取认证文件。

桌面的 `accounts/setup-plan` 只读核实同一 VPS 的部署条件，`accounts/setup-apply` 才按已确认计划准备账号所有者与服务。沿用已有工作空间公开策略的 authority/generation；没有已发布策略时仅允许确定为同一 SSH 控制来源，成员在正式纳入和授权前不能访问。外来或已修改的部署拒绝覆盖，CLI 缺失或版本不匹配保留明确说明；支持仅准备已核实的一个厂商。已有专用账号 profile 与用户文件不删除，未知回执不自动重发安装。

原账号接入重读旧公开目录并核对 ID、代次和邮箱，调用原有迁移登记逻辑；不要求手填账号 ID。中央原生登录命令复用该账号的私有 profile，三处空间无需分别登录。相同邮箱仍不作为稳定厂商账号 ID 的密码学证明，管理员需要核对实际登录账号。真实部署、官方登录、模型与出网验收仍未执行。

- CLI 安装共享一份受保护的官方可执行文件。空间不会获得 root 身份，也不会复制 root 登录目录。
- 私有登录目录只属于专用非 root 身份，由官方 CLI 登录和刷新。新路径不读出 token 再注入成员进程，不向桌面或成员分发认证文件。
- 空间会话有独立原生线程、设备路由、目录、审批和输出。Codex 当前按会话启动原生 app-server，共享账号私有 profile；不把多个空间混成一个对话，也不把一个 OS 进程当作安全保证。
- 同 owner 普通文件授权保持原规则。账号入口不授予系统盘点、root、其他设备或其他租户权限。
- 子 Agent 数量、层级、模型与重试由原生核心决定。工作台没有添加随机延迟、模拟人工操作、轮换账号或限流后自动续跑。

## 正常使用与防护尺度

授权会话架构减少凭据分发点，但账号所有者服务仍是有权限的组件；不能宣称风险最低、零风控或所有用途均被允许。官方公开能力、工程保护与真实账号行为的判定不是一回事。

保护聚焦于明确的问题：授权撤销、外来线程/审批、重复提交、已返回的原生额度耗尽或认证失败。普通网络故障、临时速率错误、仍在原生重试中的错误、模型与工具输出不会产生持久账号锁。健康会话不会因另一个会话出错被主动终止。

成员主动核实状态，原生结果确认认证和对应额度恢复后，解除对应限制，不要求管理员重复解锁正常账号。账单核查不能被无关成功状态清除。工作台不会靠重启、切账号、自动消费重置卡或重复发送绕过限制。

## Codex 新入口

`services/vps-account-broker/runtime.py` 启动固定版本官方 app-server，在原生进程内管理登录。成员通过内核 UID 验证的 Unix socket 获得会话访问，将原生工具路由到绑定的真实 Windows 执行器。

账号代次、成员 UID/空间、工作台 session、设备环境、cwd、root thread 固定在回执中。每个新回合重新核对授权与运行时策略，包括旧对话的下一条消息。更改新会话默认账号不会换掉已有受管会话的账号，也无需暂停健康的受管会话。

额度、重置卡读取通过账号所有者原生进程。兑换必须明确确认，使用原生幂等标识，没有自动消费。配给账本保留逐账号周/5小时百分比、借款来源及下周期偿还；新入口额度查询绑定来源，失败不会降级到旧 token 路径。

## 旧会话与断线

- 新入口恢复时读取原线程，不重新创建对话或重发旧消息；本地启动回执丢失时，可从所有者回执恢复原线程、回合和目录。
- 提交后没有结果的回合维持待确认。只读原生历史核对相同回合 ID；更早完成的回合不能抵销后来未知的提交。没有回合 ID 时不猜测。
- 空线程创建不执行模型。仅空线程创建回执丢失，不永久锁住整个会话。
- 可信入口明确答复未提交给模型的拒绝，与传输断线分开。桌面展示具体原因，保留会话可用性，不生成已发送的虚假消息，也不会自动重试。
- 历史缺省 `accountRuntime` 仍表示旧来源，不能当作新入口已验收；旧执行分支已删除。管理员使用 `migrate_legacy.py` 明确登记原账号并完成官方登录，只复制原生历史，桌面核对成员迁移回执后改为 `native-owner`。
- 原线程、子线程、设备、目录、消息和结果未知状态保留。分页前缀必须完整；发生原生历史回退的多个物理版本需明确活跃路径，不按时间猜测。异常时保留源历史，不能另开线程冒充恢复。
- 新入口不借用旧 H 验收。历史验收可保留作审计，但不会启用已退休路径。
- 原账号 ID/代次与数值去重 scope 保留，因此周/5小时配给、借还债务不会因迁移重新开始。未知重置卡请求通过已核对的账号映射保留原请求标识，没有自动兑换。
- 固定 `account/read` 没有可与旧 fingerprint 直接比较的账号 ID，迁移需要管理员明确确认原账号并核对原生邮箱，不以邮箱相同代替租户身份保证。

## Claude 的确切范围

Claude 管理界面可建立私有原生登录配置，生成指定账号所有者身份下的 `claude auth login` 命令，读取 `claude auth status --json` 公开状态。用户本人在其 VPS 管理终端完成官方登录；工作台没有 Claude token 输入框或订阅凭据 broker。

创建请求使用持久化 UUID。远端成功但本地响应/目录刷新丢失时，重试恢复同一个配置；只有目录确认已存在后，新的主动添加才创建另一项。Claude 与 Codex 默认选择、账号计数和代次分别处理。

**Claude Windows 本机工具执行链尚未实现完整 H，Claude 额度/重置卡接口尚无已验证实现。** 登录或勾选运行时不能解除这些缺口。当前没有启动真实 Claude 登录、模型请求或后台轮询。

“Claude 写作账号”是隔离界面验收的虚构数据，不是用户账号或产品类别。测试名称已改为“Claude 测试账号”，页面标记“合成数据，未连接 VPS”；生产代码不预置此账号。

## 运行时复选框和部署

复选框表示空间获准使用该运行时。统一入口检查 `environment.runtimes` 生成的策略。勾选不会自动安装 CLI、复制凭据或证明本机工具链可用。

仓库附带原生账号服务的 systemd unit，配置专用非 root 用户、私有目录、控制组清理和崩溃监督。未安装/启动；真实重启、原生登录、Windows 工具和 VPS 出网仍需独立验收。账号限流不会触发服务重启。

共享配给 sidecar 的热升级及开机托管仍未完成；管理员刷新可拉起已配置的按需账本，但不能把运行中的旧 helper 当作新版本已上线。已安装正式管理服务时以它为权威，不引入第二份注册表。旧会话迁移是明确的管理员操作，不自动读取/迁移真实账号。仓库已消除旧 token 执行分支，真实服务切换与独立 H 仍需后续受控部署。
