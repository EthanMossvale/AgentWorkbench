# 01 · 产品范围、优先级与难度

> 历史需求/设计基线；现行规则见 [AGENTS.md](../AGENTS.md)，实现与修订见 [文档 16](16-implementation-status.md)。本文旧方案不构成当前部署指令。 [文档导航](README.md)

初始基线：2026-09-24。当前为设计草案 v0.2；优先级已纳入翻译先行、Claude 主线和环境保险，不代表已经开始实现。

## 1. 用户需求归档

| 编号 | 需求 | 规划回应 |
|---|---|---|
| U1 | 独立 Agent 软件，摆脱现有 Codex SSH 插件的宿主限制 | 自有桌面客户端与稳定的适配层，保留原生运行时 |
| U2 | Claude 风格高级灰浅色，另有暗色；偏好 Codex 项目/会话/路径操作 | 原创双主题；项目侧栏、会话菜单、带主机身份的路径卡片 |
| U3 | 管理员 SSH 发现/复用现有工作空间，缺少再创建；可删除重建；用户不能再创建 | 自动只读发现、显式接管、幂等补齐、受控重建；独立控制面和每设备授权 |
| U4 | 检测、可选安装 Codex 或 Claude 或两者 | 按 host / workspace / runtime 展示安装与版本，安装需独立确认 |
| U5 | 两家各自独立账号、账号信息、额度、重置卡 | 两家 CLI 在 VPS 原生登录并自行保存凭据；框架只展示公开状态，不做 SDK 登录、不收集 token |
| U6 | 尽量原生满血，决定复用 CLI 还是自建轮子 | 首期只复用两家原生 CLI；通用 API harness 留在后排，不替代首期 |
| U7 | 建会话选模型家族，启动后默认不换家 | 固定会话绑定；同家模型调整与跨家交接分开处理 |
| U8 | Claude 式强度滑块、Codex 式闪电 Fast、上下文/压缩设置 | 离散强度滑块 + 独立 Fast；所有值经运行时能力校验 |
| U9 | SSH 只是模式之一，希望任意模型来工作 | RuntimeAdapter 与 ModelProvider 分层，不把 SSH 或两家模型写死 |
| U10 | 先试远端 Claude / Codex 操作本地环境，模型请求远端出网 | H 为首个原生执行目标：VPS 原生 CLI + 原生登录，SSH 提供本机手脚；独立翻译模块先行，E 不作替代 |
| U11 | 未来多 Agent 讨论组，当前不优先 | 保留 agent 身份、消息来源、调度边界；不做首版调度系统 |
| U12 | 本机 Claude CLI / 桌面长期未更新，先更新再判断 | 已分别更新到 2.1.281 / 2.7032.0，安装及能力核对见更新记录；未更新 VPS |
| U13 | 当前 VPS 已有 1 个管理员账户、3 个用户级账户 | 作为用户提供的存量环境输入，不写死数量/用户名；本轮未连 VPS 核查 |
| U14 | 已有 Codex 纯原生工具方案，应作为新项目基础 | 本轮只读核对到官方 exec-server / deferred executor 源码链及历史真实执行通过记录；先迁移复用，不从零重做 |
| U15 | 工具主要服务 Claude | 产品与原生执行验证以 Claude 为主，Codex 复用公共底座与已有链路 |
| U16 | 翻译模块先于两家 SSH 功能 | 独立第三方翻译、中文输入英文提交、可选公开进度旁注、最终原文/中文双栏 |
| U17 | 第三方翻译模型灵活接入 | 辅助协议探测、模型目录、模型/effort选择；不支持的能力如实显示，保留手动配置 |
| U18 | SSH 识别 VPS 环境并自动模拟，作为保险 | 只读 profile + 环境投影 + 已授权的真实隔离环境物化；不自动普查本机 |
| U19 | 不限制跨工作区访问其他目录文件 | 同 owner 普通文件 owner-wide；系统/设备盘点、管理员与其他租户另设边界 |

环境功能按用户明确的“保险方案”定位推进，不需要以第三方评分是否等于官方风险作为立项前提。验收目标是减少无关信息暴露、保持环境一致性和正常工作能力，不转化为免风控或绝对无法识别的保证。

## 2. 难度尺度

- 1：局部展示或明确配置。
- 2：常规交互，有有限跨平台问题。
- 3：涉及状态同步、持久化或较多边界。
- 4：跨进程/协议、恢复、账号或安全实现。
- 5：缺少稳定公开接口、强隔离或需要实验才能确认可行。

以下为工程判断，不是工期报价。难度 5 的项目可能需要缩小承诺，而非单纯增加开发时间。

## 3. 按交付优先级排序

| 顺序 | 阶段 | 功能 / 结果 | 难度 | 为什么先做 / 依赖 |
|---:|---|---|---:|---|
| 1 | P0 | 独立翻译输入闸门、原文保护、最终双栏 | 3 | 先用 mock runtime，随后真实翻译，不等待 SSH/原生账号 |
| 2 | P0 | 翻译多协议、目录/effort、可选公开进度中文旁注 | 3–4 | 完成独立模块、隐私/预算/失败策略；不是通用 Agent Harness |
| 3 | P1 | SSH VPS profile、自动投影/物化、owner-wide 文件面 | 3–5 | profile约3，文件/执行约4，强隔离覆盖约5；与Claude桥共同验收 |
| 4 | P1 | Claude 远端原生 CLI → 本机工具桥 | 5 | 主线；优先核实官方 shell 包装与文件视图候选，不提前宣称无损 |
| 5 | P1 | Codex 已有原生链的独立产品迁移与回归 | 4 | 复用已实现技术，补齐版本与全工具覆盖 |
| 6 | P1 | 出口、断线、设备/会话/环境身份与授权联验 | 4–5 | 文件与系统盘点分层，不以翻译或投影伪造实际执行位置 |
| 7 | P1 | H 纵向桌面、CLI安装/原生登录、项目会话/路径 | 4 | Claude优先，原生执行目标仍覆盖两家，登录不被翻译服务接管 |
| 8 | P1 | 存量 SSH 空间接管、补齐、分发、撤销/重建 | 4 | 优先复用现有用户环境；普通用户不能操作管理面 |
| 9 | P1 | 账号状态/额度/重置卡、双主题与模型控件 | 2–4 | 实际能力驱动；翻译模型的effort与主Agent完全分开 |
| 10 | P2 | 通用 Agent Harness + 第三方/本地工作模型 | 4 | 与P0第三方翻译区分；不替代原生登录或执行桥 |
| 11 | P2 | 不互信租户隔离、邀请制、更多系统 | 5 | 向不互信用户开放前的门槛；与P1本机隐私隔离不同 |
| 12 | P3 | 有损交接与多 Agent 讨论组 | 4 / 5 | 后置，成员身份、预算、上下文与执行权限分别管理 |
| 13 | 暂不承诺 | 跨厂商原生会话无损热切换/绝对不可识别 | 5+ | 不将不可验证的等价性或隐身保证作为产品承诺 |

P0 现在指独立翻译模块，原生桥与环境保险进入 P1；只读研究可并行，但翻译交付不能被 SSH 卡住。本轮只制定架构。原生执行阶段仍是 VPS CLI 原生登录/出网，经 SSH 使用本机环境；翻译服务的独立第三方 key 不接触两家 CLI token。

E（本地 CLI + 远端出口）仅保留为历史比较，暂不纳入项目实施、P0 实验或替代方案。SDK 资料只能辅助理解公开能力，不能成为首期可执行路线。H 遇到接口缺口时记录待核实项并继续研究原生桥接，不自动改成 E、R、SDK 或 MCP 降级方案。

## 4. 仅按难度由低到高

| 难度 | 功能 |
|---:|---|
| 2 | 暖灰/暗灰主题、布局和基础模型选择外观 |
| 3 | 侧栏管理、路径卡片、离散强度/设置校验、稳定身份与持久化 |
| 3 | 输入/结果翻译、VPS只读profile与显式环境投影 |
| 3–4 | 翻译多协议/流式旁注、保护片段与原生历史隔离 |
| 3–4 | 账号状态、额度刷新、原生重置卡的确认/幂等处理 |
| 4 | 单家原生 CLI 完整桌面适配、第二家适配、通用 API harness |
| 4 | 已有 Codex 原生 exec-server / deferred executor 链迁移为独立工作台 |
| 4 | 管理员工作空间分发、设备撤销、安装/升级/回滚 |
| 4–5 | 断线恢复、并发会话写入控制、跨主机权限与出口验收 |
| 5 | Claude 原生内核完整驱动本地执行的接口验证、不互信用户强隔离、多 Agent 协作 |
| 5 | 本机信息强隔离、宿主专用能力与owner-wide文件服务的防旁路联验 |
| 5+ | 跨厂商原生历史与内部状态的无损迁移 |

优先级与难度不是同一件事：Codex 从已有原生链迁移，Claude 用独立实验消除接口不确定性；最容易的界面不应掩盖底层能力缺口。已有原生链证据见 [基线记录](12-existing-codex-native-baseline.md)。未经目标版本与公开接口核实，不把“尚未证明”写成“不可能”。

## 5. 首版边界

建议 Windows 桌面优先，Linux 远端优先；macOS/Linux 桌面在接口上预留，不承诺首版同时验收。先服务单个所有者/可信设备，不默认开放公共多租户服务。

独立翻译模块先行，不需要原生运行时。首个原生执行模式固定为 H：VPS CLI 原生登录/出网，SSH 本机手脚，Claude优先。L/R/A不是替身，E仅历史比较。普通文件默认同owner跨工作区可达，不把当前项目边界当访问限制。

首版不做：自研大模型推理、订阅账号池/转售、跨家无损迁移、公共插件市场、完整 IDE、自动多 Agent 群聊、移动端、全盘无审批远控。

产品最低体验必须覆盖：建立项目 → 选择 VPS 原生账号/运行时（首期固定 H）→ 在本机实际读取、编辑、测试 → 审批 → 显示变化 → 断线恢复 → 会话继续。只有聊天窗口不算首版完成。
