# 13 · 独立翻译模块

> 功能与验证专题；事实仅适用于正文注明的版本、日期与验证层级。当前综合状态见 [文档 16](16-implementation-status.md)。 [文档导航](README.md)

状态：**设计草案 v0.2；本轮仅写架构文档，没有模块代码、真实翻译调用或 CLI/SSH 接入。**

## 1. 新的交付顺序与不变边界

用户要求将独立翻译模块列为下一步的首要交付：先做可单独运行、测试和演示的翻译输入/双语展示模块，再接真实第三方翻译服务，之后对接 Claude / Codex 的 SSH 原生链路。这里的 M0/M1/M2 是本模块阶段编号，与总路线图的阶段映射见第8节，不表示已经实现。

翻译是消息边界和展示层能力，不是新的 Agent 内核。后续 Agent 主链仍遵守既定 H 模式：两家 CLI 在 VPS 原生登录、由原生运行时执行模型循环，经 SSH 使用本机授权手脚。第三方翻译 API key 只属于翻译服务，不替代、提取或转换两家 CLI 的原生账号凭据。

本模块不承担：修改原生二进制、接管 CLI 登录、改造原生工具协议、代理整套模型请求、跨家会话无损迁移、获取隐藏思维链，或通过翻译与环境伪装保证规避风控。英文交互是用户体验策略，不是隐私、合规或免封承诺。

## 2. 用户可见行为

| 区域 | 预期行为 | 权威内容与边界 |
|---|---|---|
| 用户输入 | 中文自然语言先由独立第三方服务翻成英文，通过校验后才提交原生 CLI | 本地保留用户原文、实际提交文本与修订关系；翻译不能增加任务、删掉否定或扩大授权 |
| 公开 thinking / 进度 | 用户可选择在原生公开文本下方显示中文译文 | 仅翻译原生接口实际公开且允许展示的文本；不可用时不伪造、不补写 |
| final | 左侧显示原生 CLI 的真实原文，右侧显示中文译文 | 左侧不可为了满足“英文原文”外观而改写；即使 CLI 实际返回中文，也原样显示并标明语言 |
| 代码、路径与工具 | 保留原始结构、字面值与所属主机 | 翻译只作旁注，不替换工具参数、文件内容、操作结果或可执行数据 |
| 审批 | 原生操作摘要、命令、参数、目标与权限保持原样，可附中文说明 | 用户确认绑定原始操作；中文译文不能改变批准范围 |

final 的左右两栏分别标注“原生原文”和“中文译文”，提供独立复制按钮与清晰的翻译状态。窄窗口可折叠或上下排列，但不得把两栏合并成无法区分来源的一段文字。中文译文旁注明第三方翻译服务、模型和源文本版本；翻译不是另一个 Agent 的独立结论。

### 英文输出政策

通过原生 CLI 支持且可见的配置或会话指令，请求其面向用户的进度和说明优先使用英文；不修改供应商隐藏系统提示，也不保证所有原生事件都遵循语言设置。

**英文叙述偏好不改变用户指定的产物语言。** 用户要求中文文档、中文注释、某种语言的 UI 文案、指定字面量或原样引文时，必须在译后指令中保留这些要求，产物仍按指定语言生成。不得为追求“全英文链路”翻译仓库内容、文件名、用户数据、错误原文或工具结果；因此也不能承诺发送给原生模型的全部上下文都不含中文。

## 3. 独立模块结构

```text
中文用户输入
    -> 输入分类 / 受保护片段提取
    -> Translation Provider Adapter（独立账号、模型、预算）
    -> 还原与一致性校验 / 可见英文预览
    -> 单次提交边界
    -> 后续 Native CLI Adapter -> SSH / VPS 原生运行时

原生 CLI 的不可变公开事件
    -> Source Event Store -> 原生原文展示
    -> 可翻译公开文本投影 -> 翻译队列 -> 中文展示旁注
```

| 组件 | 职责 | 不负责 |
|---|---|---|
| Input Translation Gate | 输入修订、语义分段、保护、译文校验、提交状态 | 不启动 Agent 工具、不自行绕过失败 |
| Provider Registry | 用户配置的端点、协议候选、模型目录、能力与探测来源 | 不宣称任意第三方自动兼容，不扫描用户账号配置 |
| Translation Adapter | 有限协议适配、鉴权、流式/非流式翻译、超时和错误归一化 | 不登录 CLI、不提供工具执行或自有 Agent loop |
| Protected Span Codec | 占位符、原始片段、校验与精确还原 | 不依靠正则猜测即可宣称覆盖所有语法 |
| Translation Queue | 优先级、取消、有限重试、预算、事件修订去重 | 不重放原生回合或改变其执行结果 |
| Bilingual Renderer | 原文/译文对齐、公开进度旁注、失败和过期状态 | 不以译文覆盖原生历史或把翻译结果重新喂回 Agent |

建议设计对象为 `TranslationProfile`、`TranslationRequest`、`ProtectedSpan`、`TranslationResult`、`SourceEventRef` 和 `TranslationPolicy`。它们是设计名，不是已实现 API。

每个请求至少关联 owner、session、source message/event ID、source revision、方向、源/目标语言、provider、model、请求的 effort、能力来源、保护方案版本和状态。结果需记录实际可确认的生效参数、用量、错误、源版本与译文来源。未知的上游参数或费用标为 unknown，不能用请求值冒充已生效值。

## 4. 第三方协议识别、模型目录与设置

用户可配置翻译服务的 base URL、独立凭据、协议类型、模型与该模型实际支持的 effort。翻译模型与 Agent 模型在 UI、配置命名、预算和会话记录上分开；更换翻译模型不表示切换 Claude / Codex 的原生运行时或账号。

自动识别是**辅助选择**，建议流程为：

1. 用户选择已知 provider 预设，或明确输入自定义端点与凭据；先显示将访问的主机和数据范围。
2. 优先利用官方配置、返回元数据及明确支持的目录接口判断协议候选，例如 Responses、Chat Completions、Anthropic Messages。它们不是可随意互换的同一协议。
3. 端点不能可靠判别、没有模型目录、返回被网关改写或多个协议均可用时，显示候选和证据，由用户确认；支持手动协议与模型 ID。
4. 按候选协议加载上游明确支持的模型目录；目录失败不等于没有模型，目录存在也不证明每个模型支持翻译、流式或 effort。
5. 实际连通/小样本翻译测试使用非敏感样例，并由用户明确触发；提示可能计费，不在输入 key 后偷偷发起模型请求或轮询猜测大量路径。

effort 的字段、档位、语义与支持范围由对应适配器和验证结果决定。没有证据就禁用该设置或显示不支持；不把某家的 `low/medium/high`、thinking budget 或 Fast 映射成所有模型都通用的同一能力。保存请求值与实际可确认的生效值，错误不能静默吞掉后显示“已生效”。

端点使用受校验的 HTTPS；本地模型端点若后续支持，应单独列出明文连接风险和信任边界。跨主机重定向不得自动携带鉴权头；协议识别不得把凭据发送到未经用户确认的其他主机。导入的 provider 配置和远端返回说明都是不可信数据，不是修改系统或执行命令的授权。

## 5. 受保护内容：翻译前隔离，翻译后精确还原

以下内容默认不翻译、不改大小写、不做 Unicode 归一化、不重排空白或换行：

- 代码块、行内代码、Shell 命令、补丁、JSON/XML 等机器可读结构；代码中的注释默认也不由该翻译层擅改。
- Windows/Linux/UNC 路径、URL、URI、主机标识、文件名、命令参数、环境变量、模型/工具/API/事件标识符与用户要求保留的字面量。
- 工具调用参数与结果的原始载荷、审批主体/目标/权限/摘要、幂等 ID、operation ID、session ID、文件哈希和签名。
- 原生 opaque / signed / redacted 载荷；不可将其交给翻译服务解读、重建或替换。

有明确自然语言与结构化内容边界时，提取自然语言片段，用不可混淆的请求级占位符代表受保护片段；映射表留在本地可信模块中。URL 的可读标签可按策略翻译，但链接目标保持原样。无法可靠分段时，保守地保持整段不变并提示，而不是猜测后提交。

还原前校验占位符是否缺失、重复、被改写或出现在非法位置，核对受保护片段与原文逐项一致。原有结构和片段相对关系必须满足对应语法约束；不能只确认“所有标记都出现了”就认为可用。失败进入翻译失败状态，不用启发式修补后自动发送。

翻译服务只返回文本或受约束的翻译结构，不授予工具权限、不提供本地执行接口。把用户文本中的命令式句子当作待翻译内容，不让翻译模型执行任务；模型返回额外指令、工具调用或越出结构的内容时不执行。占位符与格式校验只能验证结构，不能证明语义绝对无损；否定词、授权范围、数量、日期、产物语言和条件句需进入专门质量测试。

## 6. 输入、进度与 final 的状态机

### 6.1 输入：失败默认阻断

输入流程为：`draft -> translating -> validating -> ready -> submitted`；可进入 `failed` 或 `cancelled`。用户原文修订后旧请求立即失效，晚到结果不能覆盖新文本或提交旧版本。

默认展示英文预览并允许查看原文；提交行为必须与当前输入版本及有效翻译结果绑定。翻译失败、超时、预算不足、保护校验失败或被服务拒绝时，**不自动发送中文、不偷偷更换 provider，也不把半截英文送入 CLI**。由用户明确选择：重试、编辑、取消，或本次直接发送原文。若用户选择原文，记录此次可见绕过决定；不默认为以后永久绕过。

翻译与 Agent 提交分开去重：同一输入逻辑提交不能因为重试翻译而触发两个原生回合。原生提交的回执不确定时，先按原生协议查询/恢复，不盲目重发。

### 6.2 公开 thinking / 进度：可选、异步、可暂停

仅处理原生接口确实公开的 reasoning summary、可见 thinking 文本、进度和说明事件。没有此类字段就显示不可用；不得索取隐藏 chain-of-thought、重建未公开推理，或把概括生成伪装成原始 thinking。[S01、S05、S25]

对于带签名的公开块，原生块及签名完整保留；只有明确允许展示的文本可产生独立中文旁注，旁注不替换、回传或重新签署原块。若接口不能安全分离可见文本与不透明载荷，该项不翻译。

按完整句段或稳定事件分块翻译，而非每个 token 重译整段。每份译文绑定源事件 ID 与 revision；旧结果丢弃，重复事件不重复扣预算。允许中文略滞后于原文并清楚标记“翻译中/已更新”；原生进度继续流动，不等待翻译队列。关闭进度翻译不停止 Agent。

### 6.3 final：保存原文，失败不重跑 Agent

原生 final 一到达就原样展示并保存，再以其不可变版本生成右栏中文。翻译失败、限流或取消时，左栏仍可读、可复制；右栏显示失败原因与“仅重试翻译”。不得重启 Agent、重新执行工具或生成新的原生答案来补译。

后续重新翻译保留来源和修订记录，不覆盖原始 final。译文不会写进原生 CLI 历史、替代工具结果或自动作为下一轮用户消息；只有用户明确复制/提交的内容才成为新输入。

## 7. 隐私、凭据、缓存与预算

翻译意味着把选定的用户输入或原生公开输出交给**另一家服务商**。这增加独立的数据处理方，不能因为 Agent 在 VPS 上原生运行就宣称“本机内容不出设备”。首次启用及更换服务商时，展示端点、服务商、数据类别、可能的地域/保留政策和本地缓存策略，由用户确认。

默认只发送本次待译文本和经用户允许的最小术语表，不上传完整会话、仓库、SSH 配置、账号元数据或日志。敏感项目可关闭翻译；包含秘密、个人信息或无法安全保护的内容时提示处理或阻断。代码被占位符替换不表示周围自然语言已经匿名化，也不保证第三方不会保留请求。

凭据边界：

- 翻译 key 存入系统安全凭据存储，以翻译专属引用交给可信后端；renderer、普通日志和项目 Git 不保存明文。
- 不读取两家 CLI 的 token，不从原生登录文件获取翻译 key，不把翻译 key 注入本机工具环境或远端 CLI HOME；翻译与 CLI 凭据保持不同生命周期和命名空间。
- 多用户之间不共享 key、缓存或请求历史。普通导出仅包含脱敏配置与模型选择，不包含凭据；完整凭据迁移须另行设计和授权。

缓存默认仅在本次运行/会话内使用；持久缓存需用户显式启用、设置期限并可删除。按 owner、项目/会话权限、方向、源文本版本、provider/model/effort、术语表和保护方案版本隔离。不得跨用户复用，也不能把内容哈希称为匿名化；缓存删除和本地“禁用缓存”不能撤回已经发送到第三方的数据。

预算与优先级：

- 翻译用量与原生 Agent 用量分别统计，展示 token/字符、调用数、延迟、计费来源和估算状态；费用未知不显示为零。
- 设置单次大小、并发、超时、重试上限、会话预算与可选日预算。超限时输入阻断等待用户选择；输出保留原文，暂停或排队翻译。
- 默认输入/审批辅助说明和 final 高于连续进度旁注；进度可合并、限频或由用户关闭，不能挤占 final 全部预算。
- 仅对确认适合重试的临时错误做有限退避；上游计费结果不确定时明确提示可能已计费，不保证重试免费。翻译错误不得触发 Agent 回合重放。

诊断默认只记录状态、时延、用量、错误类别与脱敏事件关联，不记录原文、译文、protected map 或鉴权头。需要内容级调试时使用合成样本；真实内容采集必须另行明确授权、限定范围和保留时间。

## 8. 分阶段交付与验收

| 阶段 | 优先级 / 难度 | 范围 | 退出条件 |
|---|---|---|---|
| M0 · 独立 mock | 第一交付 / 2–3 | 独立输入门、保护/还原、模型设置外观、模拟公开事件、final双栏、失败/取消/乱序；不连接CLI/SSH，不持有真实key，不发网络翻译请求 | 合成用例可重复演示；原文不被改写；译文失败不触发模拟Agent重跑 |
| M1 · 真实第三方 | M0后 / 3–4 | 首个明确协议和服务商、受控连通测试、模型目录/手动回退、effort能力、凭据/预算/缓存 | 用户授权后用非敏感样本实测；请求与生效参数透明；保护校验和错误处理通过 |
| M2 · 原生CLI事件接入 | M1后 / 4 | 输入提交门与原生公开事件映射，保留原生历史/签名/审批；先固定版本再扩展覆盖 | 输入只提交一次；进度旁注可关；final翻译重试不运行任何原生工具 |
| M3 · Claude / Codex SSH联验 | M2后 / 4 | Claude为首个原生主线，Codex复用已核实基线；两家分别验收 | 真实项目读改测与双语显示同时正确；位置、权限、断线恢复和翻译状态不互相污染 |

上表难度是工程判断，不是工期承诺。两家 SSH 原生能力不由翻译模块替代；M0 通过也不能称第三方已接入、原生链路已打通或语言转换已达到无损。[参见既有Codex基线](12-existing-codex-native-baseline.md)

对应总路线图：本模块M0/M1分别落入总M0-A/M0-B；本模块M2是总M0-B到M1的原生事件接口接入；本模块M3与总M1/M2两家原生联验共同完成。翻译模块和环境保险均不改变同owner普通文件跨目录访问策略。

最低测试清单：

1. 中文需求含否定、条件、数量、中文产物要求，英文译后语义不反转；“请写中文文档”仍生成中文文档。
2. 混合中英文、盘符/UNC/Linux路径、空格/中文文件名、URL查询、代码围栏、patch、JSON、标识符和引文均正确保护。
3. 占位符缺失/重复/篡改、结构破坏及语义明显异常进入失败，不能自动提交；不能把译文当审批或可执行代码。
4. 输入编辑、取消、超时、乱序响应、重复事件与提交回执不确定时，没有旧版本覆盖或双回合提交。
5. 公开进度流和签名/不透明块分别处理；未公开的思维链始终不索取、不推断、不生成伪装展示。
6. final左栏与原始事件逐字一致；右栏出错仍可使用原文；重译只产生翻译请求，不重跑Agent或工具。
7. 模型目录缺失、未知协议、不支持effort、鉴权失败、429、断网与预算耗尽有准确状态，不伪造兼容或生效。
8. 翻译key、CLI token、SSH密钥和多用户缓存互不串用；日志/导出不泄露内容或凭据；跨主机重定向不带走鉴权头。
9. M0禁用网络仍能完整演示；M1真实请求单独取证；M2/M3每家原生链路单独保存版本与验收结果。
