# 模型 API 连接

> 功能与验证专题；事实仅适用于正文注明的版本、日期与验证层级。当前综合状态见 [文档 16](16-implementation-status.md)。 [文档导航](README.md)

第三方 API 是所选 Codex 或 Claude Code 原生运行时的模型来源。工具执行、原生子 Agent 和压缩仍由该 CLI 负责；工作台不再为第三方模型启用独立通用 Agent 循环。配置入口位于「连接与运行 → 模型 API」，在「连接与环境」上方；「常规 → 工作台」提供同名快捷入口。

## 添加与管理

- 每条连接独立保存名称、地址、协议、密钥和模型映射。支持 Chat Completions、Responses、Anthropic Messages 三种兼容协议；这不是对任意私有协议兼容性的承诺。新连接的 API Key 留空便不发送密钥，不再提供单独的无密钥开关。
- 每行右侧复用技能、插件的原生样式开关。关闭后，连接及密钥仍保留；该连接的模型退出会话及子 Agent 可用目录，旧会话也不能继续调用。重新开启恢复使用。运行中、待提交或结果未知时先处理当前任务，再切换开关、编辑或删除连接。
- 保存时自动读取上游模型目录，不发起模型对话。列表以简洁的勾选行显示模型，点击「映射」才展开显示名称和上游 ID；同名模型在不同来源下具有不同标识。目录不可用时仍可手动添加模型。
- 地址输入结束、读取目录和保存时保留用户填写的前缀，不再自动添加 `/v1`。明确填写的版本保持不变；完整推理接口仍还原为基础地址。已有保存地址不会被批量删除版本段。
- 手动添加的行可用右侧垃圾桶直接移除，展开区的「移除映射」也会清除该行。保存时自动丢弃未填上游模型 ID 的草稿，包括未勾选或只填名称的行；只填 ID 时默认将其作为显示名称。
- 可以暂不选择任何模型就保存连接；目录读取失败也不会丢失连接。之后点击「编辑」可重新配置名称、地址、协议、密钥、模型选择和映射。「全选／取消全选」作用于此连接的完整模型列表，包括搜索范围外及超过前 100 行的模型。
- 更换地址、协议或模型 ID 保留手填名称、映射、思考档位、默认档位和手填上下文容量；仅作废旧来源的目录与验证证据，不把手动值伪装成已验证。刷新目录也保留手动设置。未声明的能力仍保持未知。
- 密钥仍按连接标识、地址、协议加密绑定。明确编辑同一连接并读取目录或保存时，省略 key 复用原密钥，无需重新输入；保存成功后才退役旧加密引用，失败保留旧连接与密钥。输入新值替换，点击「清除」并保存则移除。公开状态不含密钥，重定向不转发密钥，删除连接保留聊天历史。

## 简化后的执行默认值

工具与子 Agent 定义随任务默认提供，无需勾选；具体调用仍遵守模型的工具支持、用户委派授权和文件／命令审批。已有工具关闭配置在读取和保存时迁移，执行器也不再依赖旧开关。来源行右侧的总开关仍同时控制会话和子 Agent 是否可使用该连接。

工作台按回合启动或精确恢复已安装的原生 CLI。提供方配置和会话网关只作用于该子进程，不改写用户原生配置；原始 API Key 留在宿主，CLI 获得随机的会话网关凭据。输出上限优先采用上游能力和原生请求，跨协议缺省仅在必填时提供兼容值，不再暴露预算、超时或压缩表单。原生 CLI 继续执行自己的权限审批。

## 目录读取与连接排查

模型接入复用独立翻译的地址安全校验与鉴权规则，模型 API 版本和前缀由用户显式地址决定；生产路径均为 Node fetch。没有为了排错静默切换网络栈或代理。目录读取是 GET，不等于已经提交模型任务：

- 域名解析、TLS 证书、连接拒绝、连接重置及超时分别提示，原始异常内容不会回显。
- HTTP 401／403 提示密钥或权限；404／405 提示该服务未提供此目录，可以使用手动模型映射。
- 3xx 提示使用服务方给出的最终 API 地址，不转发密钥到跳转目标。不会自动重试或更换来源。
- 对话 POST 的传输中断仍按结果未知处理，避免把可能已执行的任务自动重投。

2026-10-03 兼容性修复：跨协议 Chat 请求将纯文本消息转为字符串，媒体仍保留类型；Codex 的 system/developer 输入进入目标协议的系统指令位置。网关添加最终答复工具声明时不再强制 required/any，保留原生显式工具策略，默认使用 auto；最终答复或真实工具调用的完成校验仍保留。本机网关的 `/v1/responses` 或 `/v1/messages` 是内部入口，不代表实际上游 URL，不能据此认定 HTTP 422 由版本段造成。两家 CLI 与合成上游验证不等同于重现用户真实服务的当次错误。

2026-09-28 JST 的公开无密钥检查在收到 HTTP 响应前失败：Node／隔离 Electron Node 返回 ECONNRESET，隔离 Chromium 返回 ERR_CONNECTION_CLOSED，Windows curl 报告 TLS 握手失败。这只定位到本机至服务的连接阶段，不能据此判定真实密钥失效，也未证明用户先前成功翻译时的连接条件相同；没有读取真实密钥或私有翻译配置。

## 会话与子 Agent

顶部只选择原生运行时；底部同一模型列表列出该运行时可用的 SSH 和 API 模型，SSH 来源置顶，其他来源用连接名称区分。设置中勾选、取消和批量选择不改变目录行顺序或滚动位置。空闲会话可切换来源，分别保留原生线程身份并交接新增的公开历史；不宣称隐藏推理或原生状态无损迁移。新会话及重载沿用上次明确选择的运行时、模型和思考档位，查看历史或自动创建子任务不会改变该偏好。停用或删除来源后不静默切到其他来源，发送时提示重新选择。

当前用户明确要求委派时，`workbench_list_model_targets`、`workbench_spawn_agent`、`workbench_read_agent` 允许选择任意可用目标创建、查询独立子任务。请求绑定父会话、用户授权引文、目标与幂等操作标识；重复操作不重复启动。父会话卡片在右侧打开子会话，子会话可返回上级；结果或同 owner 消息不会自主启动父会话或其他会话的新回合。已有原生子 Agent 工具及其容量、层级政策不被替换，也不强制开启。上游推理档位不是工作台的子 Agent 权限开关；不把 Ultra 推理档位当成 Codex CLI 与 Claude Code 共有的原生准入条件。原生子任务使用该提供方；跨 API 或 SSH 来源使用上述带明确授权的工作台工具。

SSH 仍走原生运行时及已有账号、H 验收、权限和出网边界。当前未完成 Claude H 验收的目标继续不可执行，不因 API 适配或合成测试解锁。API 推理从本机直连所配置上游，文件、命令运行在真实本机，不模拟 VPS 文件视图。

## 压缩归属

上下文窗口是模型能力；什么时候压缩、如何保留工具结果属于执行层策略，不存在跨接口通用的「模型压缩阈值」。

- SSH 与第三方 provider 会话均由所选原生运行时管理压缩，没有额外的工作台自动摘要模型回合。
- 上游给出的窗口大小显示于界面；Codex 同时收到 `model_context_window`。Claude 上游窗口信息用于显示，未验证向 Claude 任意模型注入可用窗口的通用原生设置，不伪装成已应用。
- 思考滑块严格使用目录实际返回的离散等级和默认值；未知时显示「上游未提供推理等级 · 使用服务默认」，不会按名称编造等级。实际请求是否正确执行该努力程度仍属于上游能力验收。
- Responses compact 和 Messages count_tokens 在原生同协议时透传；不把协议专用的服务端压缩参数发送到其他协议。兼容上游是否实现这些接口须单独确认，HTTP 转换不证明长会话压缩已经真实模型验收。

## 执行与验证边界

使用原生 CLI 自己的文件、命令、审批和子 Agent 能力；没有把旧 API 文件工具或自写推理循环包装成原生行为。原生请求经会话绑定网关转发，同协议保留不透明原生数据；跨协议只转换已实现的公开消息与工具结构，不复制隐藏推理。Chat/Messages 没有 Responses 托管搜索协议，Codex 在这些来源关闭托管 web search，原生本机工具保留。不支持的内容或工具类型明确失败。

跨协议流目前在完整上游响应后再生成原生事件；这不是逐 token 实时转换。网关对每次原生请求只转发一次，外层不会自动继续、重开任务或换账号；原生 CLI 自身的传输策略仍归 CLI。中断后结果未确认时保持未知，用户明确处理后才能继续。

验证使用真实安装的 Codex 0.155.1 / Claude Code 2.1.283、临时原生目录、合成 loopback 上游和隐藏 Electron；覆盖原生工具执行、精确线程恢复、Claude 原生审批、两家互为父子的跨来源任务，以及模型/思考偏好恢复。旧独立 ApiRunner 测试只作历史兼容检查，不是当前原生执行的证据。`test-model-api-ui.mjs` 已转向新原生验收脚本。

真实付费 API、真实 SSH 模型任务、任意供应商私有协议、长上下文压缩和本机 provider 原生 fork 未完成验收。SSH H 门禁没有变化。没有修改真实 CLI 配置、凭据、VPS、生产构建或操作用户活动窗口。详细证据见 `16-implementation-status.md`。

## 子会话与译文阅读

主会话中的子 Agent 卡片显示任务、运行时/来源、运行状态和最近公开内容。点击卡片在右侧查看子会话；原生子任务与工作台跨来源子任务共用这一阅读方式。收到的消息、工具输入/输出与嵌套子任务按顺序呈现，支持返回上级、关闭和 Esc。断线或缺少结果时显示状态未确认，不把工具已返回或父回复结束等同于子任务完成。

子 Agent 内容默认不自动翻译。主 Agent 发来的任务和子 Agent 的公开回复下方各有翻译图标，点击后仅翻译该条消息，中文显示于其下方。工具日志与隐藏思考不送入独立翻译；原文、译文分开保存，重启不会重新请求已有译文。仍在输出的消息需完成后才能翻译；失败可单独重试。

设置 → 插件 → 工作台插件 → 双语工作流中可选择：

- **右侧对照（默认）**：译文在右侧。文件或子会话占用右侧时，已有和后续译文跟随各条主消息显示；关闭阅读面板后恢复对照。
- **消息下方**：从开始就将中文译文放在对应原文下方，右侧留给文件和子会话。

子会话阅读区只显示工作台实际收到的公开事件。Claude 的 task_notification 可能只提供最终摘要；旧记录或没有提供消息/工具详情的运行时会明确显示缺失，不宣称已还原完整原生聊天档案。不会为补全界面自动扫描用户原生聊天数据库。原生子 Agent 数量/层级不因界面有界历史而受限。
