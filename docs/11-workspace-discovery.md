# 11 · 管理员 SSH：发现、接管、补齐与重建

> 历史需求/设计基线；现行规则见 [AGENTS.md](../AGENTS.md)，实现与修订见 [文档 16](16-implementation-status.md)。本文旧方案不构成当前部署指令。 [文档导航](README.md)

用户补充：现有 VPS 已有 **1 个管理员账户和 3 个用户级账户**，希望输入管理员 SSH 后自动寻找现成工作空间和密钥，存在就使用，缺少再创建，也可以删除重建。

这是用户提供的存量信息，本轮未连接 VPS 验证，也没有创建、删除或改动任何远端账户。设计不把“1+3”、用户名、路径或主机地址写死。

## 1. 默认流程

```text
管理员输入 SSH
    → 验证主机身份与管理权限
    → 自动只读发现
    → 展示现有空间/账户/CLI/公钥授权
    → 选择使用 / 接管 / 补齐 / 新建
    → 预览必要变更并确认
    → 幂等执行与验证
    → 分发设备授权包
```

“没有再创建”落实为目标状态管理：识别现有状态，只生成缺项计划；用户可在初次向导中明确批准相应自动补齐策略。单纯录入管理员 SSH、扫描失败、超时或看不到 registry，不等于授权清空旧环境。

## 2. 发现什么

按范围逐级发现，不递归搜全盘私密目录：

- 本框架 registry / workspace 标记 / 受管服务与版本（未来新环境）。
- 已知旧设备方案的 workspace 描述、用户/HOME/目录归属与服务元数据（经用户授权的兼容探测器）。
- 必要的系统用户/组和候选目录元数据，区分登录用户、系统服务账号和框架 workspace。
- Codex / Claude CLI 是否安装、可执行路径和版本；原生账号状态只从允许的只读接口获取，不读取认证文件内容。
- SSH `authorized_keys` / 证书授权的公钥指纹、设备绑定 ID、注释来源、有效期和撤销状态。
- 运行中的受管任务、占用、目录/磁盘状态，供接管或重建预览。

每条结果附来源、观测时间、权限是否充足、置信度和冲突。SSH 连接成功、Linux 账号存在、目录存在、CLI 可执行、模型已登录是五个不同状态。

## 3. 存量环境分类

| 分类 | UI 与默认动作 |
|---|---|
| 本框架已受管且健康 | 直接选择使用；重复接入不重复创建 |
| 可识别旧方案且归属明确 | 预览接管，保留用户/UID/目录/原生账号与会话；仅补登记和缺项 |
| 普通用户但无 workspace 证据 | 显示候选，由管理员指定映射；不自动当空账号覆盖 |
| 缺 CLI / 缺服务 / 缺设备授权 | 仅补缺项，不重装全部组件或重建用户 |
| 配置冲突 / 版本不兼容 | 展示冲突和可选迁移；不改原环境直到用户确认 |
| 未知归属 / 孤立记录 / 离线 | 保持只读并标记待核查；不自动删除 |

接管旧方案不是照搬其桌面插件、固定设备编号或私有账号桥。能独立复用的执行能力与需要替换的宿主耦合分别列入计划。

## 4. “找密钥”的准确含义

服务器可发现的是公钥授权及其指纹，设备的私钥原则上留在设备。存在公钥不等于当前电脑有对应私钥，也不保证授权仍有效。

- 原设备已有私钥：本地选择该身份，服务器核对授权；不默认重新生成。
- 新设备没有对应私钥：本地生成新密钥，再由管理员添加该 workspace 的设备授权；不需要重建整个 workspace。
- 旧设备遗失：撤销那台设备的 grant，重新登记；不尝试从公钥“恢复”私钥。
- 旧方案有专用私钥包：仅作为用户明确导入的敏感包处理，检查归属、加密保管与轮换；不自动扫描并汇总这些私钥。

普通分享包只含连接信息、可信主机指纹与授权引用，不含管理员私钥、原生 CLI token 或其他设备凭据。

## 5. 幂等与并发

计划关联 host ID、workspace ID、generation、预期状态摘要和操作 ID。执行前重新核对现场状态；另一个管理员已变更时重算计划，不按过时预览覆盖。

主机级管理锁防止同时创建同名账户；每一步记录未开始/进行中/完成/失败/结果未知。重连先读状态，不把创建命令重复执行。只有读不到 registry 时不能推断“没有工作空间”。

验收核心：对已有三个用户空间重复扫描、导入、重连，账号数量、UID、HOME、原生登录、密钥和其他服务均不被无故改变。

## 6. 删除并重建

将相似动作分开：**移除本机连接记录、撤销一个设备、重装运行时、重置 workspace、彻底删除 workspace**。不要用一个“删除”按钮同时覆盖这些不同后果。

“删除并重建”针对管理员已确认归属的受管 workspace：

1. 展示精确目标、所有绑定设备、运行任务、原生会话、目录与数据影响。
2. 选择保留哪些用户数据、是否保留同一所有者的原生登录、备份范围及恢复方式；凭据不得混入普通诊断包/授权包。
3. 对破坏性范围再次明确确认，禁止默认删除整个 HOME 或用户提供的任意路径。
4. 冻结新任务、结束或迁移已批准任务、撤销旧代际授权。
5. 可行时先准备/验证新环境，再切换绑定；失败保留可回退状态。需要原地销毁时必须提前说明不可逆项。
6. 新环境使用新 generation，重新核验执行端与设备 grant；相同用户名不自动继承旧会话权限。
7. 独立验证管理员 SSH、其他两个 workspace 与无关服务仍正常，最后再按保留策略清理旧资源。

重建涉及用户数据时不能仅靠 shell 字符串前缀校验，必须验证真实目标、符号链接、挂载和所有权。该流程是设计，不是本轮的远端删除授权。

## 7. 优先级与难度

P1 必须具备基础发现、复用/接管、缺项补齐与设备授权，难度约 **4/5**。删除重建的安全生命周期与恢复也约 **4/5**，在对现有环境开放该按钮前验收；不以“先删再建”缩短首次接入开发。

P0 可先做只读存量适配调研并定义数据契约，但实际连接既有 VPS 或部署/删除仍等待后续用户实施请求。
