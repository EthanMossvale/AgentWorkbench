# Claude 使用边界与协作加固（2026-09-26）

> 功能与验证专题；事实仅适用于正文注明的版本、日期与验证层级。当前综合状态见 [文档 16](16-implementation-status.md)。 [文档导航](README.md)

## 用户目标与结论

用户要求在工作台能够控制的范围内减少不必要的账号风险，保留原生能力和 Agent 协作。这里记录工程防护和可验证结果，不给出封号概率或替代厂商对具体部署的授权。

不同 Agent 可以继续协作。本轮没有禁用跨会话、跨运行时的同 owner 消息工具，也没有覆盖 Claude/Codex 原生子 Agent 的数量、层级、模型或自身重试设置。消息投递、原生回合与账号授权分别处理：收到消息或等待超时不启动新任务，不提升权限，不提供另一位使用者的订阅。

## 本轮修复

### 独立翻译凭据

- 修复之前“ASCII 字符串即接受”的缺口。保存前和 HTTP 请求前均拒绝已识别的 Claude OAuth/会话令牌前缀、Cookie/Authorization 包装及认证 JSON。旧文件中的同类值在使用时拒绝，不擅自删除或改写原密钥。
- 拒绝将 Claude 网页、登录、Console 域名配置成翻译 API；官方推理 API、用户配置的独立 API 网关与本机开发端点继续按原有规则使用。
- 拒绝操作不加密/保存新值、不覆盖旧值、不发送目录/翻译请求，错误信息不回显输入。没有读取用户现有真实密钥。
- 这是已知格式的防误用检查；无法凭任意不透明字符串证明它是 API key，也无法证明第三方网关的上游来源或授权。管理员不能据此将订阅转发网关标为合规。

涉及 `packages/translation/{credentials,config,provider}.ts` 和 `apps/desktop/host/store.ts`。

### 协作等待与重复请求

- 修复全局 revision 使无关会话变动也唤醒等待者的问题。每条消息持久化最后变更版本；read/wait 只跟踪与当前会话有关的消息。领取、原生确认和未知状态的变动保持可见，重复 operationId 不制造新变更。
- 等待结束再次核实绑定身份；等待期间账号/空间身份变化时拒绝返回旧身份的数据。旧消息日志经过版本迁移，未确认的投递仍不自动重放。
- 工具说明明确：缺少回复不意味着应改用新 operationId 重发；查证不确定投递应复用原 operationId。
- 保留同 owner 的跨运行时协作、原生子 Agent 能力及原有权限边界。没有增加并发数量或深度限制。

涉及 `packages/collaboration-core/{types,inbox,tools}.ts`。

### Claude 提交生命周期

- 只观察官方公开的 `system/api_retry` 结构化事件，显示原生重试类别、次数和退避时间。普通文本、工具输出和子 Agent 消息不会被当作主任务的重试控制信号。
- Claude 自己的重试继续由原生 CLI 管理；工作台不叠加计时重试、不杀进程重启、不自动换账号。原生重试后成功的任务仍可正常接收下一项显式任务。
- 原生最终 `result.is_error=true` 后，对当前适配器/传输阻止后续提交；已收到但尚在异步队列中的错误也必须处理后才判断下一次提交。复核原生状态后才能由可信宿主建立新的已验收连接，不能把自动新建连接当成重试逃生口。
- 拒绝空白任务，不能仅凭协作收件箱内容发起 Claude 回合；未知提交继续禁止重放。
- 此处保护**只覆盖当前适配器/传输**，不是跨应用、跨设备、跨进程重启的账号冷却或硬额度服务。Claude H 本身仍未接通；上线前须在真实 bootstrap 中验证故障状态恢复和重新连接的用户意图，不能仅凭这些合成测试开放执行门禁。

涉及 `packages/runtime-claude/{index,retry}.ts`。没有引入 Agent SDK 依赖或修改 Claude 二进制。

## 后续实现必须保持的边界

1. Claude 个人订阅由本人通过未修改的官方 CLI 原生流程登录；不把中央 Codex 账号目录扩展成 Claude 订阅共享/转发服务。多设备不自动等于多人；不得将其他人的任务偷偷挂到某个人的订阅下。
2. 工作台不接管 Claude.ai token、不伪造原生客户端身份、不改写系统/工具结果来隐藏执行来源。
3. 不新增自动发送“继续”、任务完成后重建任务、限流后自动恢复进程或用新账号绕过限制的外层循环。原生工具循环、原生子 Agent 和用户明确任务中的协作保留。
4. 持续无人值守批处理如果成为产品需求，须单独确定适用认证/商业授权与可验证的预算控制；不能由“本人使用”推导无限自动执行许可。
5. 如后续托管或分发原版 Claude Code，须单独核对商业条款、最终用户自己的认证、计费及商标要求。本轮没有对发布、销售或已有 Codex 共享方案作合规认证。

## 公开来源与解释边界

2026-09-26 实际获取了以下官方页面。源文和获取时间/SHA256 位于 `build/compliance/2026-09-26/manifest.json`，不含凭据。

- [Claude Code Legal and compliance](https://code.claude.com/docs/en/legal-and-compliance)：Pro/Max 的额度以普通个人使用为前提；区分原生订阅登录、第三方产品认证及托管未修改 CLI。该页面未给出“安全并发数/每日运行时长”。
- [Run Claude Code programmatically](https://code.claude.com/docs/en/headless)：官方提供 CLI 程序化执行、子 Agent 流和 `system/api_retry` 事件。本轮按其公开字段处理通知；没有把旧 SDK 私有控制协议或另一版本行为当作已验收实现。
- [Consumer Terms](https://www.anthropic.com/legal/consumer-terms)：核对自动访问的例外条件、账户使用及不得绕过保护措施。具体使用是否落入允许范围需结合条款，不能只看令牌类型。

本项目采取的错误锁定、令牌格式拒绝和会话级等待是保守工程决策，不是 Anthropic 公布的风控阈值。程序化运行或多 Agent 本身不能单独推出违规；反之，“原生 CLI”也不是无限使用的许可。
