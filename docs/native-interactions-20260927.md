## 结论与原缺口

工作台已经使用官方运行时，但此前主要接通了文本、工具事件和普通审批，并没有完整接回人机交互协议：

- 本机 Codex 把 `item/tool/requestUserInput` 当成未知请求终止；SSH 路径没有给这类请求回复入口。
- Claude `AskUserQuestion` 被归入普通工具审批，允许时回传未填答案的原始输入。
- MCP 信息请求、额外权限、计划进度、异步问题和请求过期缺少独立处理。
- 第一版问答控件没有接入翻译模块，且卡片、选项和留白过大。

本轮增加共用协议归一化、请求身份与单次回复、紧凑问答控件和可选翻译。答案回复到原请求，不另起用户回合；拒绝由原生运行时接收并自行决定后续行为。

## 问答翻译与紧凑展示

问答使用对话流里的紧凑块，去掉大外框和重复标题；选项为小型 radio/checkbox 和一行原文说明，译文置于对应原文下方。多题顺序显示，自定义输入聚焦时保证底部发送操作可滚动到达。浅色、深色和 860×640 窗口均检查；未操作用户正在使用的客户端。

所有新翻译能力归属现有翻译模块，不新增另一个开关：

1. **模块关闭**：不调用问题或答案翻译，不弹翻译预览。中文回答原样发送；关闭后不因历史提问自行发起翻译。
2. **模块开启**：问题、选项及说明通过独立翻译队列批量处理，保留原生文字和选项值，译文只作展示层；仍受原有外发同意、预算和翻译配置约束。
3. **选择已有选项**：回传原生选项文字，绝不把中文展示译文替换为协议键；不需要自由回答的翻译预览。
4. **自由输入中文**：沿用输入翻译设置和左下角“翻译后直接发送”。开启时翻译后回传原请求；关闭时显示紧凑预览，原稿在上、实际发送译文在下，确认后再回复。
5. **编辑或切换配置**：取消旧准备/预览；关闭模块时保留用户草稿，不自动改发原文。仍需用户再次点击发送。停止、请求过期或连接复用也不能提交旧预览。
6. **翻译失败**：不替用户提交；保留回答草稿。问题译文失败可单独重试，原问题始终可读。
7. **已回答记录**：非隐私回答保留原稿与实际提交文本，展开后在对应问题下显示；选项译文通过原标签匹配。隐私回答不进入此记录。

字段批量翻译逐字段保护路径/代码，验证键集合、字段类型和保护 token 的归属；缺项、错位、跨字段移动保护 token 时丢弃译文。结构验证不是语义质量证明。MCP 数据表单仍按原 schema 原样回传，本轮的自由文本问答翻译没有擅自改写表单 ID、URL、数值或权限。

## 为什么使用官方运行时仍需接 UI

官方引擎负责生成问题、暂停/继续、调用工具、原生上下文与 Agent 行为。宿主需要收取请求、展示问题/权限范围、收集答案、按正确 JSON 结构回复，并处理失联、取消、持久化与多窗口状态。官方运行时不会把官方桌面客户端的 React 界面或本项目的双语工作流注入工作台。

因此升级可以自然带来兼容协议内的引擎改进；新增 server request、字段、审批决定、富媒体或登录握手仍须能力探测、适配与回归。生成的 schema 对应生成它的那个 CLI 版本，不能只看工具名称猜测行为。

本轮实际例子：Codex 0.155.1 已把 `request_user_input` 放入 Default 模式工具目录，却在未启用 `features.default_mode_request_user_input` 时拒绝执行。本轮仅给工作台启动的进程增加该标志，未改用户配置；0.155.1 与已安装 0.157.1 均完成问答/拒绝探测。0.155.1 的该功能仍标为 under development，这不是未来版本稳定承诺。

推荐升级流程是：按实际运行时生成 schema/能力快照 → 对照本矩阵 → 在临时原生目录跑协议和 CLI 探测 → 隐藏桌面检查新增交互 → 再扩大已验证范围。现有 CLI 更新功能不会因此自动放开固定版本 SSH/deferred executor，也不会赋予新请求默认权限。新方法的明确不支持回执是降级方式，不是“全部自动支持”。跨 Responses/Chat/Messages 的转换也仍受 U101 已记录的功能限制。
