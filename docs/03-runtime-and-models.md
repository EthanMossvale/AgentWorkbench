# 03 · 运行时、模型、账号与设置

> 历史需求/设计基线；现行规则见 [AGENTS.md](../AGENTS.md)，实现与修订见 [文档 16](16-implementation-status.md)。本文旧方案不构成当前部署指令。 [文档导航](README.md)

v0.2交付顺序：独立翻译模块 → Claude原生桥与环境保险 → Codex已有链迁移。翻译模型不是主Agent运行时；其第三方key、effort和显示译文都不接管VPS原生登录。

## 1. 不在“全自研”和“套一个终端”之间二选一

确定首期方向：自己拥有产品外壳、会话管理、权限、设备与执行调度；Codex / Claude 两家原生 CLI 均部署在 VPS，保留原生 agent loop 并各自原生登录。框架不使用 SDK 登录、不收集或保存 token；SSH 手脚桥让原生运行时使用本机授权环境。可提供远端原生登录终端入口，但不把整套 TUI 嵌入作为最终结构化会话 UI。

| 路线 | 原生程度 | 产品可控性 | 建议 |
|---|---|---|---|
| VPS 原生 CLI 的公开协议 + SSH 原生工具契约桥 | 保留原生 loop，桥接覆盖须逐项验证 | 自有 UI + 明确适配层 | 唯一首期执行路线 |
| 官方 SDK 资料 | 可帮助理解公开 loop/工具语义 | 仅研究参考 | 不作为本项目首期可执行路线，不用于登录 |
| 原生 CLI 登录终端入口 | 保留 CLI 官方认证流程 | 只监督进程与展示交互，不读取凭据 | 首期认证入口，不是工具委派的替代方案 |
| 自建 Generic Harness | 我们控制 loop/工具/上下文 | 高，维护成本高 | 后排第三方/本地模型路线；不替代首期、不宣称等同原生 CLI |
| 修改/逆向桌面私有内部协议 | 容易随版本失效 | 表面高、长期成本高 | 不作为新产品基础 |

“原生满血”必须按能力清单兑现：shell/PTY、读写/补丁、Git、图像、MCP、skills、hooks、子 Agent、审批、resume、compaction、账号和用量。逐项标记原生、适配、受限、不可用，不使用一个没有证据的“100% 原生”标签。

## 2. Codex Native Adapter

已有原生基线优先：本轮已只读核对旧项目 `windows/helper.mjs` 与 `remote/device_server.py`，存在 **本机官方 exec-server → SSH 隧道 → VPS 官方 deferred executor/app-server** 的实现；历史验证文件记录真实模型驱动本机执行通过。它不是 MCP 模拟工具，也不只是文件面板转发。详见 [原生链路基线](12-existing-codex-native-baseline.md)。

官方将 app-server 定位于自有富客户端集成，覆盖认证、历史、审批和流式事件；提供按 CLI 版本生成协议 schema 的方式。[S01]

建议适配的能力组：

- 会话：`thread/start`、`thread/resume`、`thread/fork`、列表/名称/归档。
- 回合：`turn/start`、中断/steer、item/turn 事件、diff、usage。
- 模型：`model/list`、effort 和 capability 探测，不硬编码截图中的型号。
- 账号：由 VPS 原生 Codex CLI 完成官方登录/退出；框架只通过 `account/read`、`account/rateLimits/read` 等公开接口读取允许展示的状态，不另建 SDK 登录流程，不收集 token。
- 重置卡：服务返回可用卡片时展示；`account/rateLimitResetCredit/consume` 经用户逐次确认、幂等 key 和刷新验证执行。字段缺失不等于无卡。[S01]
- 上下文：`model_context_window`、`model_auto_compact_token_limit` 等公开配置，需校验当前版本和真实模型能力。[S02]

先复现并迁移旧方案已使用的 `exec-server / environment/add / environments` 版本化契约，再评估当前公开 Code Mode host 是否需要或适合接替。最新文档的 dynamic tools 是另一类自定义工具接口，不能混同现有原生执行器；新旧接口不可未经验证直接互换。[S01、L03]

特别区分：UI 调用的 `command/exec`、`fs/*` 与 agent loop 内部 shell / patch / image / subagent 操作。把文件面板请求转回本机，不等于模型的所有工具也在本机。

不把 `externalSandbox` 当成远程执行开关；它涉及沙箱责任边界，不自动完成工具位置迁移。[S01]

已有真实执行记录足以支持 Codex 路线具有直接工程基础；余下要做的是跨版本兼容、完整工具覆盖与独立客户端验收，而不是重新论证“是否存在原生入口”。旧方案的 VPS 账号 broker 使用 Codex 官方外部 token 协议，它不等同 SDK 登录；执行桥与认证服务应分开评估，不能直接套用到 Claude 或在接管时清空现有账号。

## 3. Claude Native Adapter：原生运行时与手脚桥

Claude Code CLI 有结构化输入输出、恢复/分叉及工具控制；具体工具契约、委派入口和能力覆盖必须以目标 CLI 版本与官方接口为准。Agent SDK 资料只可辅助研究相关概念，不构成执行或登录路线。[S05–S08]

首期只有一条路线：**未修改的 Claude Code CLI 部署在 VPS，用户通过官方原生流程登录，CLI 自行管理凭据；框架监督原生进程、展示公开状态，并经 SSH 原生工具契约桥提供本机手脚。** 不创建 Claude API/SDK Adapter 作为首期替身，不把订阅 token 提取成通用 API key。

本机 Claude Code 已按用户要求更新至 **2.1.281**，桌面端更新至 **2.7032.0**，安装后版本与签名已核实。VPS 没有更新或连接；候选 VPS 版本仍需后续独立固定。更新后的帮助确认了压缩窗口、后台会话、host 权限提示、restricted / safe mode 等入口，详见 [更新记录](10-local-claude-update.md)。这些新能力值得利用，但不能单独证明完整工具委派。

目前状态为**待目标版本和公开接口验证**，不是“Claude 不可能”。官方 Remote Control 的已有行为与所需 H 手脚桥分别核实，不能仅用 Remote Control 的执行位置推断所有公开接口的可行性。[S08–S09]

新增具体候选：官方 `CLAUDE_CODE_SHELL_PREFIX` 的shell包装入口，结合受控本机文件视图，可能保留模型可见的原生Bash与文件工具；文件工具进程仍在VPS。该入口覆盖范围、PowerShell/hooks例外、cwd/临时文件与取消语义需逐项验证，不等于Codex外置执行器。详见 [Claude桥候选](15-claude-native-bridge.md) 与 S22–S23。

桥接以原生工具名称、参数/结果 schema、流式行为、审批、取消、子任务和恢复契约为核实对象。自定义 MCP 工具不能默认替代内建工具，也不能因“能调用本地 MCP”就宣布原生手脚已打通；本轮不安排 MCP 降级路线。接口缺口须明确记录，继续研究原生契约，任何改变路线的建议须由用户另行决定。

Hooks 用于控制/观测时要核对执行时机。事后更改工具输出不撤销已经发生的远端副作用；暂停/恢复也不自然等于将执行迁走。[S10]

### 认证/分发约束

本轮官方条款页说明：产品中预装/运行 Claude Code 须满足相应条款，二进制保持未修改、保留其认证方式，终端用户使用自己的合规凭据；不得由第三方应用收集或中介 Claude.ai session token、代转订阅额度。SDK/自建产品登录与托管未修改原生 CLI 不能混为一谈。[S06]

因此账号管理保留两家原生认证，不重建 SDK 登录或提取浏览器登录态。按最新 U35，同一 VPS 的获授权工作空间共用账号目录与远端账号来源，各空间的默认选择、配置、历史与会话绑定仍独立；不会为限流自动轮换账号。当前共享目录与选择不代表跨工作空间原生认证执行已验收，实施边界见 [共享账号与原生登录](20-remote-authentication.md)。商用前需再次审查条款；此文不是法律意见。

## 4. 通用模型路线

通用 harness 面向提供可用 API 的第三方/本地模型，是为用户“任意模型”愿景保留的后排独立路线；不进入首期 H 的执行或认证链，也不能在原生桥接未完成时替代两家 CLI。未来启动该阶段后，先接一个明确协议家族，再扩展。OpenAI-compatible 不是完整行为等价；Responses、Chat Completions、Anthropic Messages 的输入、工具循环、图像与流式事件需分别适配。

模型接入至少验证：

- 认证、模型目录或手动模型 ID、流式输出与取消。
- function/tool call 参数、错误回传、并行/顺序工具、工具调用 ID。
- 图像/附件、上下文上限、输出 token 预算、用量字段的准确性。
- 多回合工具循环、拒绝与超时、重试是否造成副作用。
- effort / thinking / fast 的实际语义；缺能力就禁用控件。

不支持工具调用的模型可作为“对话/讨论成员”，不自动赋予代码 Agent 标识。任意厂商可扩展，不意味着任意模型无需测试即可执行所有工作。

通用 harness 可比较 DeepSeek Harness 的 MIT 核心及插件边界，不要求从零重写，也不因支持某种 API 就整体 fork 其桌面应用。先做依赖、模型覆盖和状态隔离审查。[S13]

## 5. 会话连续性

会话创建后固定 `runtime/provider/accountProfile/executionBinding/egressPolicy`。MVP 修改这些绑定应新建会话，保留明确来源；不能在后台替换。

同 provider / runtime 支持的模型或 effort 可在回合结束后调整，记录变更；能改型号不表示跨供应商会话可无损迁移。原生 fork/resume 也不代表工作目录快照。

跨家采用“交接到新会话”：包含用户允许的目标、摘要、文件变化、未完成事项和引用。不传令牌、隐藏推理或假造原生 tool-call 历史。UI 显示来源和有损提示；新家重新建立权限与工具状态。

## 6. 账号和额度的能力矩阵

| 能力 | Codex 原生（首期 VPS） | Claude 原生（首期 VPS） | 通用 API（后排） |
|---|---|---|---|
| 登录 | VPS 原生 CLI 官方流程；框架不收集 token | VPS 原生 CLI 官方流程；框架不收集 token | 未来独立阶段再定；非首期登录路线 |
| 公开账号状态 | 官方接口；字段可能缺失 | `auth status` 等公开状态，实际输出需版本验证 | provider 特有，可能只能验证 key |
| 额度 | 官方 rate limits，按返回桶/时间展示 | 原生公开状态/接口按目标 CLI 版本核实；字段缺失不猜测 | 通常需独立 provider 计费 API，不保证存在 |
| 额度重置卡 | 官方接口可用且有资格时接入 | 本轮未确认等价接口，不展示可用操作 | 不虚构统一能力 |
| 本地用量 | 独立事件计数、注明估算/观测 | 同左 | 同左；不可冒充账单 |

额度数据统一附 `observedAt`、来源、作用域和状态：known / stale / unknown / unsupported / unauthorized。消耗 token、账户剩余额度和费用不是同一个量。账号展示名称不等于核实的套餐档位。

重置卡只由用户明确触发；一个逻辑兑换重试复用同一幂等 key；结果不确定先查询，不能偷偷再消费一张。绝不为了绕过限流自动轮换账号。

## 7. 配置策略

每项设置包含请求值、实际生效值、能力来源和生效时机。UI 保存成功不等于 runtime 已接受。启动时冻结能力快照，版本变更后重新探测。

上下文设置表示允许使用/估算的预算，不提升模型真实最大窗口。压缩阈值必须低于有效上限，并预留系统/工具/输出空间；不支持自定义阈值的 runtime 显示原生管理，不能存一个无效数字。

Fast、effort、模型 ID 为三个独立维度；Fast 仅在模型/账号/运行时提供时启用，展示费用或额度差异来源。没有可靠来源时显示待确认，不写固定倍率。[S02、S04、S11]

## 8. 文件、环境与翻译契约

原生适配器需要支持同owner普通文件跨工作区访问，不能一边在UI承诺owner-wide，一边偷偷保留原生工具的当前workspace围栏。仍需遵循OS权限、动作审批、设备和租户边界；无法实现的能力列为缺口，不宣布通过。

环境查询使用版本化VPS profile；真实工具能力和执行位置单独保留。需要强信息隔离时，原生Shell/插件应在真实隔离环境执行；任意未隔离宿主代码不能仅凭投影保证隐私。不得改写原始文件或工具输出来假装来自VPS。参见 [环境保险](14-environment-projection.md)。

翻译只改变经用户启用的自然语言输入与显示译文，不修改工具参数、审批、原生thinking签名或会话权威历史。主Agent仍收发原生协议；原文、实际发送英文和译文分别关联保存。参见 [独立翻译模块](13-translation-module.md)。

## 2026-09-26 实现补记

紧凑输入框左下为权限，右下为上下文圆环、模型/思考档位和发送；模型弹层采用 Claude Code 风格的简洁控件与离散滑块，不增加 hover 提示。输入框下仅一个翻译按钮，直发/本次原文等在点击后展开；账号和运行时切换位于会话顶部。原生目录与最新用量的协议实现、验收及 Claude 未接通边界见 [当前实现记录](16-implementation-status.md)。窗口大小和压缩阈值目前仍由原生管理，不将 U8 的自定义参数入口标成已完成。
