# 防御性设计逐点源码台账（2026-10-03）

旧报告将多处限制合并成 100 个主题，没有满足逐项审批要求。本次将源码位置、条件子项、人工设计判断分别保留，不以 100 或其它数量为上限；任何候选都不会因为已达到某个数量而被丢弃。

**当前完成的是文件清单和静态控制点展开，不是全部设计的逐项人工确认。** 普通返回、业务分派、测试断言及资源释放也可能被语法扫描命中。不能把记录数当作独立防御设计数量，也不能让用户替代审计者判断数万条普通分支。人工审阅仍需清理误报、追踪调用方和合并同一行为的多处证据；未完成部分在台账中显式标为候选。

## 审批入口

运行下面三个命令后，用浏览器打开本地 `build/qa/defensive-audit-expanded/review.html`。页面与相邻的 `review-data.js` 必须一起保留。页面不联网、不启动工作台、不加载真实用户资料，也不执行任何审批对应的修改。

```sh
node scripts/audit-defensive-designs.mjs
python scripts/audit-defensive-designs.py
python scripts/render-defensive-audit.py
```

1. 默认显示产品源码里的动作候选，必要性低的排在前面。可以筛选“已有人工设计判断”，或切换到全部范围查看安装器、开发脚本、测试和配置。
2. 每个源码点有稳定 `F` 编号、相对路径、行列、函数、完整触发条件、动作、外层条件和源码快照。条件子项有父条件入口。相同位置关联多个 D 项时全部显示，不能只批准一项就删除整行。
3. 对每项选择“移除”“保留”“改为可配置”“修改方案”“非防御/无需审批”或“待核实”，可附说明。浏览器本地保存，使用“导出审批 JSON”交付决定；换浏览器时导入该文件。重新扫描不会修改旧导出的决定。
4. 也可直接回复 `D101 移除` 或 `F… 保留`。建议、优先级、用户决定是不同字段；未决定条目始终待审批。

已有 D001–D100 见[旧总览](defensive-design-audit-20261003.md)，新增单列行为见[补充人工审阅](defensive-design-supplement-20261003.md)。这些 D 项仍可能包含旧的主题归并，不能用新的总数替代全面审计。

## 范围、提取方式与限制

- 文件范围为 `git ls-files` 的全部受版本控制文件，含已暂存的新文件；每个文件记录 SHA-256、所属范围、提取方法和记录数。未跟踪文件、被忽略的产物、依赖和仓库外的原生运行时不在扫描范围内。
- TS、TSX、JS、MJS、CJS 使用 TypeScript AST；Python 使用 Python AST。涵盖条件、条件原子、抛错、返回、异常处理、循环跳过/中止、循环条件、分派分支、短路与默认值、过滤/限额/校验调用、策略参数及 JSX 限制属性。
- C#、PowerShell、Shell、安装脚本、HTML/CSS、配置及嵌入脚本使用候选行提取，不声称完成对应语言的语义解析。Python 字符串内位置是相对字符串字面值的证据，不能直接当作生成脚本的真实行号。Markdown、图片等非可执行文件仍列入清单并说明排除。
- 名称相关调用、动态生成代码、跨函数状态机和依赖内部策略不能仅靠语法规则证明穷尽；常规业务分支也可能是误报。动作层是便于优先审阅的语法分类，不是“全部确认有害”的列表。
- 本次读源明确发现：字体发现的阈值与错误缓存、安装器关闭/下载/命名限制、只读 SSH 有限重试、托盘失败降级、登录扩展停用/取消等需要分别审批，不能藏在通用校验一项下。原生记忆收据错误码映射本身只是诊断归类，真正拒绝逻辑需看调用方。
- 所有扫描器只读源文件，不导入或执行被审计代码。未读取私钥、登录凭据或用户聊天数据库，未连接 SSH，未改变产品防御规则。

## 必要性排序

从低到高依次为：人工建议移除、名单/固定阈值的静态初判、必要性未定、完整性/权限的静态初判、人工建议保留。同级按文件和源码位置排列。人工建议中的“改为提醒/配置/补适配”不等于可以直接删除条件。

人工判断保存在 `scripts/defensive-design-reviews.json`，含相对源码路径和定位片段，随仓库保存，可从新检出复现，不依赖旧的本地审计产物。关键词初判会受嵌套节点影响，只作为排查顺序；卡片始终提供完整代码，不以这一分数替代调用链审阅。F 编号由文件、语法类型、归一化代码及同内容出现顺序生成：单纯行号移动不变，但重复代码顺序变化可能改变编号。实施前必须重新核对当前代码与导出快照。

## 输出与证据

输出位于被忽略的 `build/qa/defensive-audit-expanded/`，不提交生成快照或用户审批记录：

| 文件 | 用途 |
| --- | --- |
| `review.html` / `review-data.js` | 分页审批和完整源码快照 |
| `ledger.json` | 全部控制点、候选、关联判断、文件清单 |
| `approval.csv` | 无行数截断的平面导出；复杂长源码以 JSON 为准 |
| `summary.json` | 基线、分类数量、解析错误、扫描后变化文件 |
| `inventory.json` / `sources.json` | 原始提取结果与对应源码 |

解析错误与扫描后文件变化会在页面显示，不得将存在这些问题的文件宣称为已完整扫描。扫描统计以实际生成的 `summary.json` 为准；文件数会随本次审计工具本身纳入 Git 而变化。静态源码证据不等于真实桌面、原生模型或远端执行验收。

## 工具接口及验证范围

`extractTypescript(file, source)` 和 `extract_python(file, source)` 返回源码记录，不执行被审计文件。三段 CLI 默认使用上述输出目录，可通过第一个参数指定其它输出目录。第二、三段读取前段产物；缺失文件/语法错误由诊断或进程失败体现，不静默当作审计成功。页面导入/导出对象为 `{head, decisions: {[id]: {decision, note, file, line}}}`，不直接执行改码或授权。

这是离线开发审计工具，不注册生产命令、服务、设置、主题、surface 或持久配置。插件调用/注册/替换与生产 UI 偏好迁移不适用；生产 API、权限与生命周期不变。工具可替换提取/渲染脚本，保留记录字段即可消费同一数据。审批页搜索、分页、展开是临时查看状态；决定和备注独立保存，可导出迁移。

运行 `node scripts/test-defensive-audit.mjs` 验证 TS/Python 合成语法样本、真实受控源码解析、ID 唯一性、条件父项链接、人工条目全部可定位、编号精确搜索、快照哈希回查及隔离浏览器审批导入/导出。浏览器验证使用临时无界面 Edge，不操作正在使用的浏览器。未实施任何用户尚未审批的删除。
